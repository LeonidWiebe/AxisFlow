## 1. Что это (пересмотрено)

**AxisFlow** — переиспользуемый модуль **координатного ввода** для FreeCAD 1.1.1 (C++),
повторяющий эргономику MicroStation **AccuDraw**: компас в опорной точке, прямоугольный (орто)
и полярный (радиальный) ввод, локи осей, «умный» лок по направлению курсора, «просто начни
печатать».

Ключевой тезис: **AxisFlow даёт точки, он не создаёт геометрию.** Его продукт — ввод (компас,
лок, режим, единицы, клавиши, подтверждённая точка). Объекты документа строит потребитель.

Потребители: любые верстаки, команды и макросы — через публичный Python API. AxisFlow **ничего
не знает** ни об одном потребителе; зависимость строго односторонняя. Ведущий сценарий, под
который проектируется API (тяжёлый C++-верстак со своими командами рисования), живёт в
отдельном репозитории и в этом коде не упоминается.

Термины: **rect = орто** (контур-квадрат, поля X/Y), **polar = радиальный** (контур-круг,
расстояние/угол). В коде `rect`/`polar`, в UI — орто/радиальный.

## 2. История: почему отказались от интеграции с Draft

Первые итерации строили AxisFlow как надстройку над Draft/BIM через хук на `Snapper.snap`.
Это работало для геометрии, но воевало за ввод. Разбор исходников Draft 1.1.1 показал, что
**Draft уже содержит почти всю нашу функциональность**, только под другими именами:

- `DraftToolBar.constrain(val)` ставит `Snapper.mask` и снимает повторным вызовом — это лок оси;
- `Snapper.constrain(point, basepoint, axis)` проецирует на ось рабочей плоскости
  (`DraftVecUtils.project`) — это наша математика лока;
- `checkSpecialChars()` реализует in-command шорткаты; в 1.1.1 по умолчанию
  `RestrictX='X'`, `RestrictY='Y'`, `RestrictZ='Z'`, `Global='G'`, `Relative='R'`, `Length='L'` —
  ровно те буквы, которые перехватывал наш глобальный фильтр (лобовой конфликт);
- `setMouseMode(False)` + параметр `MouseDelay` — штатная «защёлка» набранного значения
  (по умолчанию 1 секунда, поэтому набранное значение затиралось курсором);
- `displayPoint()` при маске сам гасит лишние поля и уводит фокус в залоченное;
- `tb.globalMode` / чекбокс `isGlobal` / шорткат `G` — штатный переключатель
  «глобальные координаты ↔ система рабочей плоскости».

Плюс `_orig_snap` уже применяет маску (`fp = self.cstr(lastpoint, constrain, point)`), так что
наш солверный лок поверх давал **двойное ограничение**.

Вывод: `FreeCADGui.Snapper` и `FreeCADGui.draftToolBar` — не «поле какого-то инструмента», а
**канонический ввод координат** всего Draft-семейства (Draft, BIM/Arch, CAM `PathGetPoint`,
аддоны поверх Draft). Держать рядом второе окно ввода = структурная конкуренция за фокус, лок,
относительность, единицы. Sketcher этой трубой не пользуется (свой C++ `DrawSketchHandler`).

Решение: **AxisFlow владеет вводом в собственных инструментах** и не пытается отнять ввод у
чужих. Форк Draft отвергнут: команды обращаются к живому объекту `FreeCADGui.Snapper`, а не к
нашей копии исходников; затенение ядрового модуля ломает BIM/CAM/аддоны.

## 3. Контракты библиотеки (принятые решения)

1. **Публичная граница — Python API.** Никакой C++-линковки потребителями: не нужны
   `dllexport`, разделение Core/Gui, установка заголовков, `AxisFlowConfig.cmake`.
   Сборка остаётся одним `AxisFlow.pyd`.
2. **Цикл ввода принадлежит AxisFlow (C++).** Движение курсора, солвер, компас, панель — внутри
   C++. В Python уходит только **подтверждённая точка** (раз на клик). Поэтому граница
   Python пересекается редко, и «C++-потребитель через Python API» не является горячим путём.
   Если потребителю понадобится живое превью на каждом движении — добавится `movecallback`
   (как в Draft); при упоре в производительность вернёмся к C++-слою.
3. **Одна активная сессия ввода одновременно.** `AxisFlowService` остаётся синглтоном (решение
   принято сознательно). Это выстрелит только при двух 3D-видах / двух одновременных
   инструментах. Чтобы миграция на `AxisFlowSession` осталась дешёвой: всё состояние трогать
   **только через сервис**, не раздавать наружу ссылку на солвер (публичный `solver()` подлежит
   удалению из API).
4. **Ядро не создаёт `DocumentObject`.** Ни линий, ни арматуры. Точка расширения —
   `pointConfirmed` / колбэки `getPoint`. Геометрию строит потребитель (можно через готовое
   `Draft.make_line/make_wire/make_circle` — эти функции живут в `draftmake/*` и **не трогают**
   `Snapper`/`DraftToolBar`, конфликта нет).
5. **Draft-адаптер — опциональный плагин** (`axisflow_snap.py`). Все адаптерные костыли живут
   только в нём и не протекают в ядро.
6. **Настройки — `ParameterGrp`** (`User parameter:BaseApp/Preferences/Mod/AxisFlow`). Это и есть
   XML (`user.cfg`), но в пользовательском каталоге: гарантированно доступен на запись,
   переживает переустановку, читается из C++ и Python одинаково, позже бесплатно даёт страницу
   в настройках FreeCAD. Экспорт пресета в отдельный XML — опция на будущее.
7. **Команды рисования — не наша задача.** Демо-команда «линия» существует как **эталонный тест**
   полного цикла ввода и живёт **вне ядра**. Прямоугольник/дуга/круг не добавляются: они ничего
   нового про ввод не проверяют. Полноценный чертёжный верстак (условно DrawFlow) — отдельное
   продуктовое решение, принимается отдельно.

## 4. Среда сборки (Windows)

- Windows, MSVC (Visual Studio 17 2022), x64. Qt6, Coin4, FreeCAD 1.1.1 в **pixi**-окружении.
  Модуль линкуется с `OpenGL::GL` (`find_package(OpenGL)`) — компас включает сглаживание точек
  сырыми `gl*`-вызовами (круглые точки), символы `glEnable/glBlendFunc/...` живут в `opengl32`.
- FreeCAD env (pixi): `C:/projects/FreeCAD111/.pixi/envs/default`; FreeCAD src `…/FreeCAD111/src`, build `…/FreeCAD111/build/release`.
- Проект: `C:\projects\AxisFlow`; установка: `%APPDATA%\FreeCAD\Mod\AxisFlow\`. Путь берётся у FreeCAD (`getUserAppDataDir()`), не захардкожен; в этой среде разрешается в `…\FreeCAD\Mod\` (без `v1-1` — прежнее предположение про версионированный каталог здесь не подтвердилось). Переопределяется `-DFREECAD_MOD_DIR=...`.
- Собрать в песочнице ассистента нельзя (нет FreeCAD SDK) — код пишется аккуратно,
  пользователь собирает у себя и присылает ошибки.
- Добавление/переименование исходников → **чистая реконфигурация** (см. §8).

## 5. Архитектура кода

- **AxisFlowSolver** (`src/AxisFlowSolver.*`) — чистая математика. Ни Qt, ни Coin. Режим,
  плоскость (u/v/n), origin, keyboard-оверрайды; solved-точка, local offset,
  distance/angle, `nearestAxis()`. Матрица компаса: столбцы = оси, world→local = транспонирование.
  **Модель локов (переработана):** поле либо свободно (следует за курсором), либо зафиксировано
  (держит значение). Фиксация — один механизм со слотами оверрайдов (`_kX/_kY/_kZ/_kDist/_kAngle`,
  NaN-сентинелы); битовая маска `LockBit`/`lockMask()` помечает лок-происхождение слота
  (галка/клавиша/SmartLock) в отличие от набранного значения. `lockValue*` фиксирует со взводом
  бита, `setValue*` (набор) бит снимает. Различие нужно индексированию: набранное значение гасит
  точку-кандидата (`typedEntryActive`), лок — нет; ось-кандидат гасится при `inPlaneLocked`
  (rect: X|Y; polar: D|A). «Движение только вдоль оси» = композиция двух локов (SmartLock).
  Полярная ветка применяет `_kDist/_kAngle` — полярный лок закрыт этой же унификацией.
- **AxisFlowService** (`src/AxisFlowService.*`) — singleton-`QObject`, мозг. Владеет солвером и
  состоянием. Сигналы `stateChanged`, `activeChanged(bool)`, `pointConfirmed`, `cursorMoved`.
  Карта клавиш + `performAction`. Локи: `toggleFieldLock(field)` (mode-mapped 0/1/2, как
  `setKeyValue`; свободное поле замораживается на ПОКАЗАННОМ значении — компонента solved-точки
  из `indexing()`, со снапом/индексацией; фиксированное — освобождается), `setSlotLock/clearSlotLock/
  slotLocked(LockSlot{X,Y,Z,Dist,Angle})`, `clearLocks()` (снимает только лок-слоты, набранные
  значения живут; действие ClearLocks чистит и их через `clearKeyValues`). `smartLockToggle()`:
  rect — по `nearestAxis` фиксирует ДВА других поля в 0 (X→лок Y=0,Z=0; Y→лок X=0,Z=0); polar —
  лок угла на ближайшие 0/90/180/270° + Z=0, дистанция свободна; повторное нажатие снимает все
  локи. Действия: LockX/LockY только в rect, LockD только в polar (поле D), LockZ — в обоих.
  `setDisplayLock(AxisLock)` — display-only зеркало Draft-маски для адаптера (действует лишь при
  `constrainEnabled==false`, сбрасывается при включении). `setConstrainEnabled(bool)` — выключается **только** в
  Draft-адаптере (там Draft уже ограничил точку); в собственном пути всегда `true`.
- **AxisFlowSettings** (`src/AxisFlowSettings.*`) — singleton-`QObject` поверх `ParameterGrp`.
  Все опции компаса + горячие клавиши. Сигнал `changed()`. См. §6.
- **Hotkeys** (`src/AxisFlowHotkeys.*`) — карта `Qt-код → AxisAction` + имена действий
  (`name()/fromName()`) для сериализации. Без `Q_OBJECT`.
- **AxisFlowCompass** (`src/AxisFlowCompass.*`) — Coin3D сцен-граф (блок B, сделан): контур с
  прозрачной заливкой + чёткая точка в центре; **ось Z не рисуется**; контур — квадрат (орто) /
  круг (радиальный) через `SoSwitch`; оси X/Y (цвет, толщина, начало, длина) из настроек;
  геометрия строится в локальной системе компаса и ставится `SoTransform`, поэтому `setPlane()`
  реально кладёт компас в рабочую плоскость. Видимость — корневой `SoSwitch`. Радиус задаётся в
  **мировых** единицах: перевод из пикселей делает `AxisFlowTool` по камере. **Живая направляющая**
  (guide, центр компаса → курсор) настраивается: вкл/выкл, стиль (сплошная/пунктир/точки/штрих-
  пунктир), цвет — из настроек (`LiveLine*`), применяется в `applySettings()`; API `applyGuideStyle()`.
- **AxisFlowPanel** (`src/AxisFlowPanel.*`) — плавающая Qt-панель (singleton при главном окне,
  `Qt::Tool | FramelessWindowHint`): заголовок + кнопка выключения, редактируемые поля с единицами,
  галки лока, и кнопка **системы координат** под полями. Кнопка НЕ дублирует режим: она
  переключает ридаут/ввод **Local ↔ World** (`_worldFrame`); режим орто/радиальный — на `Space`,
  виден по подписям полей (X/Y/Z ↔ D/A). World = те же оси компаса, но от мирового нуля
  (`value_i = localOffset_i + origin·axis_i`); ввод конвертируется обратно в локальный оверрайд.
  Поведение ввода (AccuDraw): первый символ заменяет живой readout (по полю, а не по устаревшему
  `_entryField` — иначе после Tab дописывалось); голая магнитуда получает **знак направления**
  курсора по оси (`signedByDirection`, см. `AxisFlowEntry.h`), явный знак важнее; при потере
  фокуса значение округляется до принятой точности и нормализуется по единицам (`reformatField`).
- **AxisFlowTool** (`src/AxisFlowTool.*`) — на один 3D-вид. Владеет компасом. Standalone:
  Coin-колбэк (курсор + клики + клавиши) — это **основа будущего собственного ввода**.
  Adapter: курсор гонит Snapper. **Teardown отложен** (`deleteLater` инструмента и key-фильтра,
  `disconnect` от сервиса в `deactivate()`): завершать команду можно прямо из обработчика события,
  которым владеет сам инструмент, без use-after-free.
- **AxisFlowEventFilter** (`src/AxisFlowEventFilter.*`) — глобальный key-filter, нужен **только**
  адаптеру (в собственном инструменте клавиши приходят в Coin-колбэк).
- **AxisFlowEntry.h** (`src/AxisFlowEntry.h`) — header-only чистая политика ввода без Qt/Coin
  (`signedByDirection`): знак магнитуды по направлению курсора, явный знак важнее. Вынесено из
  панели, чтобы покрыть Tier-1 юнит-тестом.
- **AxisFlowIndexing.h** (`src/AxisFlowIndexing.h`) — header-only чистая политика «индексирования
  живой линии» без Qt/Coin (`computeIndexing`). Два независимых снапа (по дистанции и по осям)
  работают в пикселях (принимает `worldPerPixel` от камеры) и только в локальном фрейме. Солвер
  хранит состояние (индексированная дистанция, флаги, допуск, view-scale, фрейм) и вызывает её из
  `getSolvedPoint()`, так что клик автоматически ставит точку в кандидат. Компас рисует точку-
  кандидата (дистанция) и ось-кандидата (ось); толщина/прозрачность оси-кандидата и прозрачность
  живой линии — из настроек. Покрыто Tier-1 (`tests/test_indexing.cpp`).
- **Command.cpp / Workbench** — четыре команды на палитре: `AxisFlow_Activate` (тумблер компаса),
  `AxisFlow_DrawLine` (запускает демо `axisflow_demo.line()` — точка входа, геометрия в демо),
  `AxisFlow_ToggleLiveLine` (вкл/выкл живой линии), `AxisFlow_Settings` (окно настроек). У каждой
  `sPixmap`; иконки — SVG в `Resources/icons/`, грузятся с диска через `addIconPath` (в InitGui),
  `.qrc` пустой. Значок верстака — `AxisFlow.svg`.
- **AxisFlowPy** (`src/AxisFlowPy.cpp`) — Python-биндинг, статический `g_session`. Плюс геттеры
  оверрайдов (`getValueX/Y/Z/Dist/Angle` в солвере, `keyValue(idx)` в сервисе) — их использует
  `reformatField` для показа знакового значения.
- **axisflow_settings.py** — живой немодальный диалог настроек (Python/PySide): двухстолбцовый
  грид имя→значение, редактор по типу (чекбокс/спинбокс/дабл-спинбокс/комбо/кнопка-цвет), приме­
  нение на лету через `AF.setSetting` (без OK). Диалог секционирован (табы слева, горизонтальный текст: `QListWidget`+`QStackedWidget`) — разделы Compass / Live Line / Behaviour (бывш. Snapping) / Hotkeys; расширяется одной строкой в нужной секции `_SECTIONS`.
  Открывается командой `AxisFlow_Settings`. Ограничение: пока открыт, не подхватывает внешние
  изменения (`changed()` не проброшен в Python), перечитывает при повторном открытии.
- **axisflow_snap.py** — опциональный Draft-адаптер: оборачивает `Snapper.snap`, зеркалит
  `Snapper.mask` в UI (display-only), продлевает штатную защёлку Draft (`setMouseMode` +
  `mouse_delay_input_start`), выключает наше ограничение (`setConstrainEnabled(False)`).

Действия для ключей клавиш (дефолты = hotkeys.ini): `ToggleMode` (Space), `ConfirmPoint` (P),
`SmartLock` (Return/Enter), `LockX/Y/Z/D` (X/Y/Z/D), `SetOrigin` (O), `RotateTop` (T),
`RotateFront` (F), `RotateSide` (S), `RotateByView` (V), `RotateCycle` (E), `FinishLine`
(Escape), `CancelCommand` (backtick); без дефолта: `ToggleActive`, `ClearLocks`, `CancelEntry`. Семантика Lock*: заморозить поле на
текущем значении (галка ставится, поле перестаёт следовать за мышью), повторно — снять; LockX/Y
только в орто, LockD только в радиальном, LockZ везде (при привязке пинит высоту в системе
компаса). Enter СТАВИТ точку (commit набранных координат). **Escape = FinishLine**
(завершить текущую линию, сессия живёт), **backtick = CancelCommand** (завершить всю команду).
`SmartLock`/`ClearLocks`/`CancelEntry` — без дефолтной клавиши, доступны через API. `setSetting`-имена
опций: те же, что в таблице, camelCase (`compassSize`, `liveLineEnabled`, `liveLineStyle`, `liveLineColor`, …).

GUI-редактор — `axisflow_settings.py` (команда `AxisFlow_Settings`): двухстолбцовый грид, тип
поля по значению, применение на лету (см. §5). Все 12 опций из таблицы там представлены; каждая
завязана на `AF.setSetting`, что шлёт `changed()` → компас/панель обновляются мгновенно.

## 7. Статус

**Готово и в проекте:**
- Солвер (орто/полярный, **локи-фиксации полей** — единый механизм с оверрайдами + `LockBit`-маска,
  включая полярные D/A; smart-lock двумя полями; keyboard-оверрайды, world↔local, nearestAxis),
  сервис-синглтон с сигналами, настройки на `ParameterGrp`, карта хоткеев.
- Компас Coin3D (контур+заливка+точка, квадрат/круг, без Z, поворот к WP, «всегда показывать»,
  постоянный размер в пикселях) + настраиваемая **живая линия** (вкл/выкл, стиль, цвет).
- Панель: редактируемые поля с единицами (в полярном режиме теперь ТРИ поля — D/A/Z), активное
  поле по nearestAxis, Tab-цикл, галки лока (галка = поле заморожено: лок ИЛИ набранное значение;
  клик по галке замораживает/освобождает; в адаптере display-only зеркало Draft-маски —
  «движение вдоль X» показывается галками на Y и Z),
  «просто печатай», кнопка **Local/World**; ввод AccuDraw — знак по направлению
  (`AxisFlowEntry.h`), первая цифра заменяет, округление/нормализация единиц при потере фокуса.
- Инструмент/стейт-машина `Idle/Tracking/Finished`, continue-режим; **Escape = FinishLine**
  (завершить линию, сессия живёт), **backtick = CancelCommand**; **teardown отложен**
  (`deleteLater`+`disconnect`), завершать команду безопасно из своего же обработчика.
- Публичный `getPoint(callback, movecallback, last, continuous, finishcallback)`; мост
  `GetPointBridge`. Рабочая плоскость подхватывается потребителем (`AF.setPlane` из активной WP).
- **Палитра**: четыре команды с иконками (`Activate`, `DrawLine`, `ToggleLiveLine`, `Settings`) +
  значок верстака; **живой диалог настроек** (`axisflow_settings.py`).
- **Демо-линия** (вне ядра): многосегментная, собственное Coin-превью, транзакции/undo на каждую
  линию, снятие выделения с готовой линии; Escape — новая линия, backtick — конец.
- Draft-адаптер (`axisflow_snap.py`); зеркало Draft-маски переведено на display-only канал
  `setDisplayLock` (реальные локи в адаптере не создаются).
- **Переработка локов (июль 2026):** галка = заморозка поля. LockX/Y/Z/D фиксируют поле на текущем
  значении; SmartLock фиксирует два «чужих» поля в 0 (движение строго вдоль ближайшей оси; в
  полярном — угол на 0/90/180/270 + Z=0); после постановки точки локи сбрасываются (per-point).
  Старый одноосевой `setAxisLock` (зануление off-axis) удалён; Python `lockAxis` принимает
  'x'|'y'|'z'|'d'|'a'|'none' и стал идемпотентной установкой, `getState()['lock']` заменён на
  `getState()['locks']` (dict по слотам). Ось-кандидат остаётся видимой, пока лок прижимает
  точку к оси (SmartLock-пара, поле, замороженное ровно в 0, полярный угол кратный 90°):
  `IndexingInput.lockedOnAxisX/Y` взводят `axisActive` ДО гейтов кадра/масштаба — это фидбек
  лока, не мягкое индексирование; геометрию компас берёт из solved-точки, она уже на оси.
- **Индексирование живой линии** (локальный фрейм): снап по дистанции (точка-кандидат на конце
  живой линии при приближении длины к запомненной «индексированной дистанции») и по осям (ось-
  кандидат вместо живой линии при приближении к оси X/Y). Допуск в пикселях, чистая математика в
  `AxisFlowIndexing.h`, снап зашит в `getSolvedPoint()`, визуалы в компасе, 6 новых настроек,
  Python-API (`setIndexedDistance/clearIndexedDistance`, поля в `getState`), Tier-1+Tier-2 тесты.
  Нюансы: точка-кандидата гасится во время ввода координаты в поле (введённое значение важнее
  снапа); пока активен любой кандидат — точка (снап длины) или ось (обнуление перпендикулярной
  компоненты) — поля X/Y/Z (или D/A) синхронизируются со снапнутой точкой, иначе показывают сырой
  курсор. Точки (центр компаса и кандидат) круглые (`GL_POINT_SMOOTH`, линк с `OpenGL::GL`).
- **Автотесты**: Tier 1 — C++ gtest (`tests/`, солвер+хоткеи+`AxisFlowEntry`; gtest компилируется
  из исходников прямо в раннер, 73 кейса (солвер+хоткеи+entry+indexing), `run_tests.bat`/`ctest`, headless); Tier 2 — Python API
  (`TestAxisFlow.py`, 22 кейса, гоняется в GUI-FreeCAD `Test.runTestsFromModule`). Оба зелёные.

- **Объектные привязки (Draft Snapper)**: своих не пишем — зовём FreeCAD'овские через тонкий
  Python-мост `axisflow_snapping.py` (`snap(x,y,ox,oy,oz,has_origin) -> (px,py,pz,hit)`),
  который дёргает `AxisFlowTool::querySnap` по C-API (модуль кэшируется, ошибки глушатся —
  привязки никогда не ломают инструмент). `constrain=False`: ограничения наши, Draft не должен
  применять их второй раз. `lastpoint` = центр компаса — без него не работают extension/
  parallel/perpendicular/ortho. Факт привязки определяется по видимости снап-маркера Draft
  (`Snapper.tracker.Visible`), т.к. `snap()` возвращает точку всегда.
  Приоритеты: введённое значение → лок поля → привязка → индексирование → сырой курсор.
  Привязанная точка становится «точкой размещения» (`getLocalOffset` берёт её вместо курсора),
  поэтому лок проецирует именно её, а поля X/Y/Z показывают реальные 3D-координаты привязки
  (компонента Z больше не обнуляется). Сырой курсор при этом сохраняется — по нему «удержание
  оси» решает, по какой оси едет пользователь.
  **Удержание оси при привязке** (безусловное, бывшая настройка «SmartLock» в разделе Snapping —
  удалена в июле 2026): если в момент привязки курсор шёл вдоль оси в допуске индексирования,
  точка ОСТАЁТСЯ на этой оси — привязка отдаёт вдоль-осевую координату, прочие компоненты
  обнуляются, ось-кандидат горит. Курсор вне оси — привязка авторитарна, кандидаты гаснут.
  Гейты: включено осевое индексирование; при явном локе ветка не нужна — лок прижимает сам.
  Идея: точка всегда остаётся на оси, вдоль которой двигается курсор. Ключ `SmartLock` в
  `ParameterGrp` больше не читается (остатки на диске безвредны). Палитра привязок —
  переиспользуем команды `Draft_Snap_*` в своём тулбаре (состояние общее с Draft/BIM).
- **Переводы регенерированы (июль 2026)**: полный прогон пайплайна lupdate→перевод→lrelease
  по всем фичам этой волны — 75 строк на язык, 23 новых (Behaviour-опции, Control/View hotkeys,
  SetOrigin/Rotate*-метки, Freeze-формулировки), 5 устаревших вычищено (`-no-obsolete`), во всех
  восьми языках 75/75 finished, .qm пересобраны.
- **Анимация поворота компаса** («Compass rotation animation (s)», ключ `CompassRotateAnimation`,
  float 0..2 c клампом, дефолт 0.5; 0 = мгновенно): чисто визуальная — солвер переключает
  плоскость сразу, компас доворачивается slerp'ом со smoothstep-изингом на `SoTimerSensor`
  (~60 fps) внутри `AxisFlowCompass::setPlane`. Ключевое: display-базис `_u/_v/_n` (по нему
  считается живая линия) интерполируется в ногу с трансформом (`applyRotationNow` выводит его из
  той же SbRotation), иначе конец линии «отклеивался» бы от курсора на время анимации; финальный
  кадр ставит точный целевой базис (без числового дрейфа). Первый setPlane после создания —
  мгновенный (активация не должна «выплывать» из identity); ретаргет на лету стартует из текущей
  интерполированной позы, так что быстрые T-F-S цепляются плавно. Сенсор гасится в деструкторе.
- **Пакет view/origin-действий и починка ToggleActive (июль 2026):**
  `SetOrigin` (O) — перенос origin компаса в текущую solved-точку (со снапом) БЕЗ подтверждения
  точки: `setOriginToCursor()` в сервисе не эмитит `pointConfirmed`, команда рисования указание
  игнорирует; чистит typed-значения/локи, взводит follow-референс; компас перепривязывается сразу
  (синк origin добавлен в `onServiceStateChanged` тула). `RotateTop/Front/Side` — фикс-базисы
  через `setPlane` (Front: n=−Y, v=+Z, u=+X; Side: n=+X, v=+Z, u=+Y); `RotateCycle` (E) — цикл
  Top→Front→Side с досевом индекса из явных Rotate*; `RotateByView` (V) — сервис эмитит
  `alignToViewRequested`, тул строит базис из ориентации камеры (right/up/back). **ToggleActive
  починен**: фильтр событий при выключенном сервисе теперь перехватывает ровно одну клавишу —
  привязанную к ToggleActive (ShortcutOverride+KeyPress, с inScope-гейтом) — раньше выключение
  было односторонним. Дефолты built-in переписаны зеркально hotkeys.ini (Insert свободен,
  ConfirmPoint=P, SmartLock=Enter). Диалог: вкладка Hotkeys разделена на «Control hotkeys» и
  «View hotkeys»; ConfirmPoint/ClearLocks/CancelEntry из окна убраны (остались биндуемыми через
  API/ini, метки для конфликт-диалога — в `_HIDDEN_ACTION_LABELS`). Адаптер unbind'ит все новые
  буквы (P/O/T/F/S/V/E) — однобуквенные шорткаты Draft внутри его команд не крадутся.
- **«Компас следует направлению»** («Compass follows direction», ключ `CompassFollowDirection`,
  int 0..2 с клампом, по умолчанию 0=Выкл, enum-строка в Behaviour): при подтверждении точки
  компас довворачивается по отрезку «предыдущая точка → новая». Режим 1 («оставить Z») —
  проекция отрезка на текущую плоскость становится осью u, нормаль не меняется; режим 2
  («полностью») — u = направление отрезка, нормаль берётся максимально близкой к старой
  (Грам-Шмидт; отрезок вдоль старой нормали → новой нормалью становится старая v). Математика —
  `AxisFlowSolver::rotateToDirection(dir, keepNormal)` (Tier-1). Поворот происходит в `confirm()`
  ДО переноса origin и гейтится флагом `_hasFollowRef`: свежая сессия (`beginInput` →
  `clearFollowReference()`) не вертит компас по отрезку от «прошлогоднего» origin; засеянная
  база (`setOrigin`, т.е. `last` в getPoint) флаг взводит — первый же отрезок валиден. Внешний
  `setPlane`/`resetPlane` поворот перекрывают штатно.
- **«Переход фокуса при движении»** («Focus advance on movement», ключ `FocusAdvanceOnMove`,
  по умолчанию включён, раздел Behaviour): после набора значения в поле X (Y) осознанное движение
  курсора (> 6 px, порог в `focusAdvanceExceeded` из `AxisFlowEntry.h` — чистый предикат под
  Tier-1) завершает ввод и переносит каретку в смежное поле Y (X); в полярном — D↔A. Введённое
  значение остаётся оверрайдом, поле переформатируется как при blur. Якорь перевзводится каждым
  принятым нажатием (`pushFieldValue` — единая воронка ввода), так что дрожание мыши во время
  набора ввод не крадёт; без камеры (`viewScale()<=0`) не срабатывает. Дизарм: Enter/Tab/blur/
  Escape/пустое поле/подтверждение точки. Поле Z в переходе не участвует. После перехода
  взводится `_advanceHold`: авто-таргетинг по nearestAxis заморожен (иначе курсор, всё ещё
  прижатый к прежней оси, украл бы каретку обратно); холд снимают Tab, Escape и постановка точки.
- **Знак-от-направления стал опциональным** («Smart negative direction», ключ
  `SmartNegativeDirection`, по умолчанию включён): без знака введённая величина берёт знак
  направления курсора по оси (гейт — в `pushFieldValue` панели; чистое правило
  `signedByDirection` в `AxisFlowEntry.h` не изменилось). Выключено — знак буквально как введён.
  Раздел настроек «Snapping» переименован в «Behaviour», галка живёт там.
- **Вкладка Hotkeys в диалоге настроек**: третий раздел (после Compass / Live Line) со списком
  действий, кнопкой захвата клавиши (клик → «Press a key…» → нажатие), кнопкой ✕ и «Restore
  default keys». Отказ от Ctrl/Alt/Meta (их фильтр всё равно не перехватывает), предупреждение
  при конфликте (карта — key→action, поэтому назначение отбирает клавишу у другого действия).
  Новое C++/Python API: `setHotkeys(action, [codes])` (список — чтобы не терять вторую клавишу
  у `ConfirmPoint`) и `resetHotkeys()` (чистит только `Hotkey.*`, прочие опции не трогает).
- **`package.xml` требует `<subdirectory>./</subdirectory>`** в `<content><workbench>`: если тега
  нет, FreeCAD подставляет `<name>` и ищет `Mod/AxisFlow/AxisFlow/InitGui.py` → верстак молча

  Проявляется только когда `package.xml` реально установлен в Mod (см. install-правило).
- **Дефолтные хоткеи в `hotkeys.ini`** (россыпью в Mod, не в `.qrc`): правятся без пересборки.
  Слои, позже — сильнее: встроенный layout в коде (фолбэк, битый/отсутствующий файл не ломает
  старт) → `hotkeys.ini` → пользовательские привязки в `ParameterGrp`. Парсер в
  `AxisFlowSettings::loadHotkeyDefaultsFile` (имена клавиш через `QKeySequence::fromString`,
  raw-коды, инлайн-комментарии `;`/`#`, одиночный символ = сама клавиша, отказ на
  `Qt::Key_unknown` с предупреждением в Report view). Путь подаёт `InitGui.py`; API
  `AxisFlow.loadHotkeyDefaults(path)` перечитывает без рестарта. Есть install-правило в CMake.
- **i18n (по политике FreeCAD)**: интерфейс следует глобальному языку FreeCAD (Preferences →
  General → Language) — своего переключателя нет, при первом старте берётся язык FreeCAD.
  Строки помечены `translate("AxisFlow", …)`/`QT_TRANSLATE_NOOP` (Python, диалог настроек) и

  Инструмент `update_translations.py`
  (`pylupdate`/`lupdate`→`lconvert`→`lrelease`), гайд `TRANSLATING.md`. `.qm` едут в поставке
  (стейджинг + NSIS). Проверено: `.qm` резолвит строки по контекстам (диалог/команды/панель).

## 9. Ошибки сборки, УЖЕ решённые (не наступать снова)

1. `LNK1104 python311.lib` → `target_link_directories(... "${PYTHON_ROOT}/libs")`.
2. «No module named» → нужен `.pyd`: `set_target_properties(... PREFIX "" SUFFIX ".pyd")`.
3. «DLL load failed» → `os.add_dll_directory(...)` в `InitGui.py`.
4. python311 vs python312 → пиннинг на pixi-env (`Python3_ROOT_DIR`, `Python3_FIND_STRATEGY
   LOCATION`, `Python3_FIND_REGISTRY NEVER`, `Python3_FIND_VIRTUALENV FIRST`) + чистая реконфигурация.
5. `C2196`: в Coin `SoKeyboardEvent::RETURN` и `ENTER` — один код (65293), нельзя оба как `case`.
6. Не-ASCII в runtime-строках: `QLatin1String("\u2014")` на MSVC даёт мусор (UTF-8 байты как
   Latin-1). Использовать `QString(QChar(0x2014))`. Символы без глифа (⏻ U+23FB) — заменять на
   `QStyle::standardIcon`.
7. **Путь установки — всегда спрашивать у FreeCAD, не хардкодить.** CMake берёт путь через
   `getUserAppDataDir()` и добавляет `Mod/AxisFlow`. В этой среде он разрешается в
   `%APPDATA%\FreeCAD\Mod\AxisFlow` (ранее предполагали версионированный `v1-1\Mod` — здесь не
   подтвердилось). Если поставить не туда, куда смотрит запущенная FreeCAD, воркбенч не
   регистрируется, `InitGui.py` не выполняется, `import AxisFlow` → `ModuleNotFoundError`,
   `Gui.activateWorkbench` → `KeyError`. Переопределяется `-DFREECAD_MOD_DIR=...`.
8. Имя воркбенча для `Gui.activateWorkbench(...)` — **`AxisFlowWorkbenchPy`** (имя класса в
   `InitGui.py`), а не `AxisFlow`/`AxisFlowWorkbench`.
9a. **Модель фокуса (главное про ввод).** Каретка ВСЕГДА стоит в активном поле панели
   (`AxisFlowPanel::focusActiveField()`). Пока `QLineEdit` в фокусе, он сам поглощает цифры,
   Backspace и стрелки — и глобальные шорткаты FreeCAD не срабатывают. Ронять фокус нельзя
   нигде: `clearFocus()` после Escape приводил к тому, что следующая цифра уходила в
   `Std_ViewTop`. Клик в 3D-виде отдаёт фокус вьюпорту, поэтому `confirmPoint()` возвращает
   каретку обратно. Первый набранный символ очищает поле (иначе допишется к живому readout).
   Панель — окно `Qt::Tool`, значит для каретки её надо `activateWindow()`.
9. **Клавиши нельзя ловить в Coin-колбэке.** FreeCAD вешает на голые цифры глобальные `QAction`
   (`2` → `Std_ViewTop` и т.п.), а Qt разрешает шорткаты **до** доставки события виджету 3D-вида.
   Итог: «просто начни печатать» молча меняет вид камеры. Правильный механизм — фильтр на `qApp`,
   который принимает `QEvent::ShortcutOverride` для «своих» клавиш (тогда `QAction` не срабатывает
   и приходит обычный `KeyPress`) и там же делает работу. То же касается `Space`
   (`Std_ToggleVisibility`).
10. **GoogleTest на MSVC+pixi: компилировать из исходников, не линковать библиотеку.** Отдельная
    `gtest.lib` в этой связке (clang-флаги pixi на MSVC-линии) не подхватывалась — `MakeAndRegister­
    TestInfo` оставался unresolved. Решение: добавить `gtest-all.cc`+`gtest_main.cc` прямо в цель
    тест-раннера и поставить include gtest первым. Заголовки и определения гарантированно совпадают.
11. **`InitGui.py`: раздельные globals/locals.** FreeCAD исполняет init-скрипт так, что имена,
    присвоенные на верхнем уровне (`_icons_dir`), НЕ видны внутри тела класса. Обращение к ним из
    тела `class Workbench` даёт `NameError`. Ставить такие значения (например `Icon`) на верхнем
    уровне после `class`, а тело держать литеральным.
12. **Кнопка на палитре ≠ окно.** Команда живёт в C++ (`Command.cpp`); чтобы кнопка появилась,
    нужна свежая `.pyd` с зарегистрированной командой И **полный перезапуск** FreeCAD (Python-
    верстак строит тулбар из `self.list` раз за сессию). Открытие окна из консоли работает и без
    зарегистрированной команды, поэтому «окно есть, кнопки нет» = не пересобрано/не перезапущено.
    Отсутствие иконки кнопку НЕ прячет (нерезолвнутый `sPixmap` → кнопка без картинки). Проверка:
    `"AxisFlow_Settings" in FreeCADGui.listCommands()`.
13. **Иконки грузятся с диска** через `FreeCADGui.addIconPath(Resources/icons)` в `InitGui.py`;
    `Resources/AxisFlow.qrc` пустой (плейсхолдер). Имя `sPixmap` должно совпадать с именем SVG без
    расширения. Новую иконку достаточно положить в `Resources/icons/` (в install попадёт через
    `install(DIRECTORY Resources ...)`), рекомпиляция не нужна.
14. **`wireTracker` из Draft не для списка точек.** Его конструктор и `update()` ждут Part-wire
    (`.Vertexes`), не list Vector — падал молча. В демо превью рисуется собственным Coin-узлом.

## 10. Известные ограничения

- Одна активная сессия ввода (следствие синглтона, §3.3).
- Компас: размер в пикселях пересчитывается на движении курсора и смене настроек, но не на
  «чистом» зуме без движения мыши. Цвет заливки и обводки не настраиваемые (настраивается только
  прозрачность заливки).
- Собственный ввод есть; впереди — полноценные относительные/абсолютные режимы ввода сверх
  текущей World-конверсии по осям.
- Teardown сессии безопасен на Qt-путях (backtick/Escape). Остаётся узкий Coin-side случай:
  `AF.endSession()`, вызванный синхронно внутри point-callback не-continuous потребителя, всё ещё
  делает `unref` Coin-узла на его собственном стеке. Демо (continuous + отмена через Qt) не задевает.
- Sketcher не поддержан (свой C++ `DrawSketchHandler`, отдельная большая задача).
- Диалог настроек (`axisflow_settings.py`) применяет изменения на лету, но пока открыт не
  подхватывает внешние изменения (например, кнопку «Toggle live line»): `changed()` не проброшен
  в Python. Перечитывает значения при повторном открытии. Лечится поллингом или пробросом сигнала.
- Панель только плавающая (`Qt::Tool`); докируемый вариант обсуждён, но не сделан.
- Draft-адаптер: значение, впечатанное вручную в поле Draft, подчиняется локу Draft, но не нашему;
  это нормально — в адаптере лок и есть Draft'овый.

## 12. Конвенции

- `QT_NO_KEYWORDS` → `Q_SIGNALS/Q_SLOTS/Q_EMIT`.
- Типы: `Base::Vector3d`, `Base::Matrix4D`; Coin — `SbVec3f`.
- Комментарии в коде — английский; общение — русский.
- `PreCompiled.h` — первым инклюдом.
- Q_OBJECT-классы → в `qt6_wrap_cpp(MOC_SOURCES ...)` (AUTOMOC не используется). Классы без
  сигналов/слотов (Hotkeys, EventFilter) в MOC-список не добавлять.
- Никаких не-ASCII символов в runtime-строках (см. §9.6).
- Иконки — SVG в `Resources/icons/`, имя = `sPixmap`; грузятся через `addIconPath` (диск), не qrc.
- Путь Mod — только через FreeCAD (`getUserAppDataDir()`), не хардкодить.
- Чистую тестируемую логику выносить в header-only без Qt/Coin (пример — `AxisFlowEntry.h`) и
  крыть Tier-1 gtest. После правок — прогонять `run_tests.bat` до продолжения.

## 14. Релиз и распространение

AxisFlow — **компилируемый C++-верстак** (`AxisFlow.pyd`). Addon Manager его не соберёт: внешние
верстаки в нём обязаны быть Python-only. Официальные пути — хостить прекомпилированные бинарники
самому либо вливаться в ядро FreeCAD. Выбран первый: **GitHub Releases с готовым ZIP** под
конкретную версию/платформу FreeCAD.

**ABI-замок:** `.pyd` грузится только в FreeCAD с совпадающими Python/Qt/Coin ABI — собирать против
той же дистрибуции, что у пользователей, и проверять ZIP на чистой установке. Имя вида
`AxisFlow-0.1.3-win64-FC1.1.zip`.

Инструменты: `make_release.bat` (собирает рантайм-папку `dist/AxisFlow` — только `.pyd`+`.py`+
`Resources`+`package.xml`+`LICENSE` — и жмёт ZIP через PowerShell), `package.xml` (метаданные),
`LICENSE` (полный LGPL-2.1), `RELEASE.md` (чеклист выпуска и инструкция установки), раздел
Installation в README. Опции на будущее: коммит прекомпилированной `.pyd` в репозиторий для
Addon-Manager custom-repo (одна платформа/ABI), Windows-инсталлятор (Inno/NSIS).
