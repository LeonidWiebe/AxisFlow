## 1. Что это (пересмотрено)

**AxisFlow** — переиспользуемый модуль **координатного ввода** для FreeCAD 1.1.1 (C++),
повторяющий эргономику MicroStation **AccuDraw**: компас в опорной точке, прямоугольный (орто)
и полярный (радиальный) ввод, локи осей, «умный» лок по направлению курсора, «просто начни
печатать».

Ключевой тезис: **AxisFlow даёт точки, он не создаёт геометрию.** Его продукт — ввод (компас,
лок, режим, единицы, клавиши, подтверждённая точка). Объекты документа строит потребитель.

Потребители: любые верстаки, команды и макросы — через публичный Python API. AxisFlow **ничего
не знает** ни об одном потребителе; зависимость строго односторонняя. Ведущий сценарий, под
который проектируется API (тяжёлый C++-верстак со своими командами рисования), живёт в
отдельном репозитории и в этом коде не упоминается.

Термины: **rect = орто** (контур-квадрат, поля X/Y), **polar = радиальный** (контур-круг,
расстояние/угол). В коде `rect`/`polar`, в UI — орто/радиальный.

## 2. История: почему отказались от интеграции с Draft

Первые итерации строили AxisFlow как надстройку над Draft/BIM через хук на `Snapper.snap`.
Это работало для геометрии, но воевало за ввод. Разбор исходников Draft 1.1.1 показал, что
**Draft уже содержит почти всю нашу функциональность**, только под другими именами:

- `DraftToolBar.constrain(val)` ставит `Snapper.mask` и снимает повторным вызовом — это лок оси;
- `Snapper.constrain(point, basepoint, axis)` проецирует на ось рабочей плоскости
  (`DraftVecUtils.project`) — это наша математика лока;
- `checkSpecialChars()` реализует in-command шорткаты; в 1.1.1 по умолчанию
  `RestrictX='X'`, `RestrictY='Y'`, `RestrictZ='Z'`, `Global='G'`, `Relative='R'`, `Length='L'` —
  ровно те буквы, которые перехватывал наш глобальный фильтр (лобовой конфликт);
- `setMouseMode(False)` + параметр `MouseDelay` — штатная «защёлка» набранного значения
  (по умолчанию 1 секунда, поэтому набранное значение затиралось курсором);
- `displayPoint()` при маске сам гасит лишние поля и уводит фокус в залоченное;
- `tb.globalMode` / чекбокс `isGlobal` / шорткат `G` — штатный переключатель
  «глобальные координаты ↔ система рабочей плоскости».

Плюс `_orig_snap` уже применяет маску (`fp = self.cstr(lastpoint, constrain, point)`), так что
наш солверный лок поверх давал **двойное ограничение**.

Вывод: `FreeCADGui.Snapper` и `FreeCADGui.draftToolBar` — не «поле какого-то инструмента», а
**канонический ввод координат** всего Draft-семейства (Draft, BIM/Arch, CAM `PathGetPoint`,
аддоны поверх Draft). Держать рядом второе окно ввода = структурная конкуренция за фокус, лок,
относительность, единицы. Sketcher этой трубой не пользуется (свой C++ `DrawSketchHandler`).

Решение: **AxisFlow владеет вводом в собственных инструментах** и не пытается отнять ввод у
чужих. Форк Draft отвергнут: команды обращаются к живому объекту `FreeCADGui.Snapper`, а не к
нашей копии исходников; затенение ядрового модуля ломает BIM/CAM/аддоны.

## 3. Контракты библиотеки (принятые решения)

1. **Публичная граница — Python API.** Никакой C++-линковки потребителями: не нужны
   `dllexport`, разделение Core/Gui, установка заголовков, `AxisFlowConfig.cmake`.
   Сборка остаётся одним `AxisFlow.pyd`.
2. **Цикл ввода принадлежит AxisFlow (C++).** Движение курсора, солвер, компас, панель — внутри
   C++. В Python уходит только **подтверждённая точка** (раз на клик). Поэтому граница
   Python пересекается редко, и «C++-потребитель через Python API» не является горячим путём.
   Если потребителю понадобится живое превью на каждом движении — добавится `movecallback`
   (как в Draft); при упоре в производительность вернёмся к C++-слою.
3. **Одна активная сессия ввода одновременно.** `AxisFlowService` остаётся синглтоном (решение
   принято сознательно). Это выстрелит только при двух 3D-видах / двух одновременных
   инструментах. Чтобы миграция на `AxisFlowSession` осталась дешёвой: всё состояние трогать
   **только через сервис**, не раздавать наружу ссылку на солвер (публичный `solver()` из API
   уже убран, см. §11.11 — правило действует и дальше: новых геттеров, отдающих солвер наружу,
   не заводить).
4. **Ядро не создаёт `DocumentObject`.** Ни линий, ни арматуры. Точка расширения —
   `pointConfirmed` / колбэки `getPoint`. Геометрию строит потребитель (можно через готовое
   `Draft.make_line/make_wire/make_circle` — эти функции живут в `draftmake/*` и **не трогают**
   `Snapper`/`DraftToolBar`, конфликта нет).
5. **Draft-адаптер — опциональный плагин** (`axisflow_snap.py`). Все адаптерные костыли живут
   только в нём и не протекают в ядро.
6. **Настройки — `ParameterGrp`** (`User parameter:BaseApp/Preferences/Mod/AxisFlow`). Это и есть
   XML (`user.cfg`), но в пользовательском каталоге: гарантированно доступен на запись,
   переживает переустановку, читается из C++ и Python одинаково, позже бесплатно даёт страницу
   в настройках FreeCAD. Экспорт пресета в отдельный XML — опция на будущее.
7. **Команды рисования — не наша задача.** Демо-команда «линия» существует как **эталонный тест**
   полного цикла ввода и живёт **вне ядра**. То же и у Move/Copy/Extrude: все они — обычные
   потребители `getPoint`, ядро по-прежнему не создаёт ни одного `DocumentObject`. Прямоугольник/дуга/круг не добавляются: они ничего
   нового про ввод не проверяют. Полноценный чертёжный верстак (условно DrawFlow) — отдельное
   продуктовое решение, принимается отдельно.

## 4. Среда сборки (Windows)

- Windows, MSVC (Visual Studio 17 2022), x64. Qt6, Coin4, FreeCAD 1.1.1 в **pixi**-окружении.
  Модуль линкуется с `OpenGL::GL` (`find_package(OpenGL)`) — компас включает сглаживание точек
  сырыми `gl*`-вызовами (круглые точки), символы `glEnable/glBlendFunc/...` живут в `opengl32`.
- FreeCAD env (pixi): `C:/projects/FreeCAD111/.pixi/envs/default`; FreeCAD src `…/FreeCAD111/src`, build `…/FreeCAD111/build/release`.
- Проект: `C:\projects\AxisFlow`; установка: `%APPDATA%\FreeCAD\Mod\AxisFlow\`. Путь берётся у FreeCAD (`getUserAppDataDir()`), не захардкожен; в этой среде разрешается в `…\FreeCAD\Mod\` (без `v1-1` — прежнее предположение про версионированный каталог здесь не подтвердилось). Переопределяется `-DFREECAD_MOD_DIR=...`.
- Собрать в песочнице ассистента нельзя (нет FreeCAD SDK) — код пишется аккуратно,
  пользователь собирает у себя и присылает ошибки.
- Добавление/переименование исходников → **чистая реконфигурация** (см. §8).

## 5. Архитектура кода

- **AxisFlowSolver** (`src/AxisFlowSolver.*`) — чистая математика. Ни Qt, ни Coin. Режим,
  плоскость (u/v/n), origin, keyboard-оверрайды; solved-точка, local offset,
  distance/angle, `nearestAxis()`. Матрица компаса: столбцы = оси, world→local = транспонирование.
  **Модель локов (переработана):** поле либо свободно (следует за курсором), либо зафиксировано
  (держит значение). Фиксация — один механизм со слотами оверрайдов (`_kX/_kY/_kZ/_kDist/_kAngle`,
  NaN-сентинелы); битовая маска `LockBit`/`lockMask()` помечает лок-происхождение слота
  (галка/клавиша/SmartLock) в отличие от набранного значения. `lockValue*` фиксирует со взводом
  бита, `setValue*` (набор) бит снимает. Различие нужно индексированию: набранное значение гасит
  точку-кандидата (`typedEntryActive`), лок — нет; ось-кандидат гасится при `inPlaneLocked`
  (rect: X|Y; polar: D|A). «Движение только вдоль оси» = композиция двух локов (SmartLock).
  Полярная ветка применяет `_kDist/_kAngle` — полярный лок закрыт этой же унификацией.
- **AxisFlowService** (`src/AxisFlowService.*`) — singleton-`QObject`, мозг. Владеет солвером и
  состоянием. Сигналы `stateChanged`, `activeChanged(bool)`, `pointConfirmed`, `cursorMoved`.
  Карта клавиш + `performAction`. Локи: `toggleFieldLock(field)` (mode-mapped 0/1/2, как
  `setKeyValue`; свободное поле замораживается на ПОКАЗАННОМ значении — компонента solved-точки
  из `indexing()`, со снапом/индексацией; фиксированное — освобождается), `setSlotLock/clearSlotLock/
  slotLocked(LockSlot{X,Y,Z,Dist,Angle})`, `clearLocks()` (снимает только лок-слоты, набранные
  значения живут; действие ClearLocks чистит и их через `clearKeyValues`). `smartLockToggle()`:
  rect — по `nearestAxis` фиксирует ДВА других поля в 0 (X→лок Y=0,Z=0; Y→лок X=0,Z=0); polar —
  лок угла на ближайшие 0/90/180/270° + Z=0, дистанция свободна; повторное нажатие снимает все
  локи. Действия: LockX/LockY только в rect, LockD только в polar (поле D), LockZ — в обоих.
  `setDisplayLock(AxisLock)` — display-only зеркало Draft-маски для адаптера (действует лишь при
  `constrainEnabled==false`, сбрасывается при включении). `setConstrainEnabled(bool)` — выключается **только** в
  Draft-адаптере (там Draft уже ограничил точку); в собственном пути всегда `true`.
- **AxisFlowSettings** (`src/AxisFlowSettings.*`) — singleton-`QObject` поверх `ParameterGrp`.
  Все опции компаса + горячие клавиши. Сигнал `changed()`. См. §6.
- **Hotkeys** (`src/AxisFlowHotkeys.*`) — карта `Qt-код → AxisAction` + имена действий
  (`name()/fromName()`) для сериализации. Без `Q_OBJECT`.
- **ПТН и «путь компаса»** (июль 2026). **ПТН** — предполагаемая точка нажатия: точка, которая
  будет поставлена прямо сейчас, со всеми блокировками (это `getSolvedPoint()`, в компас приходит
  через `setCursorPoint()`). **Путь** — тонкая пунктирная ломаная от центра компаса через ПТН к
  точке привязки. Показывается при активной привязке (`snapActive`) ИЛИ когда заморожено любое
  поле (`anyFieldFixed()` — набранное значение или лок, то есть в точности галка в панели).
  Форма зависит от того, какие ПЛОСКОСТНЫЕ поля заморожены:
  | заморожено | ломаная (локальные координаты, плоскость = z=0) |
  |---|---|
  | ничего | центр → (px,py,0) → ПТН |
  | U (X) | центр → (px,0,0) → (px,py,0) → ПТН |
  | V (Y) | центр → (0,py,0) → (px,py,0) → ПТН |
  | U и V | центр → (px,0,0) → (px,py,0) → ПТН |
  Замороженная нормаль (Z) форму не меняет — только длину последнего звена. Если точка привязки
  не совпала с ПТН (а это ровно случай, когда лок перебил часть привязанной точки), добавляется
  ещё одно звено ПТН → привязка. Вырожденные звенья выбрасываются, поэтому лок оси на нуле или
  точка в плоскости просто дают меньше вершин, а не висячий штрих.
  Настройки — в разделе **Live Line** диалога (`CompassPathEnabled` по умолчанию true —
  «Draw path to the point», плюс стиль и цвет): путь это рисование линий, поэтому лежит рядом с
  живой линией, а не в Compass.
  Геометрия вынесена в **`AxisFlowPath.h`** — header-only, без Coin/Qt/FreeCAD, вход и выход в
  локальных координатах компаса (перевод в мир — дело компаса, ему нужен базис). Покрыто Tier-1
  (`tests/test_path.cpp`, 15 кейсов на все ветки). В радиальном режиме поля 0/1 — это дистанция и
  угол, они не ложатся на звено вдоль оси, поэтому инструмент передаёт lockU/lockV = false и путь
  рисуется по первой строке таблицы.
  Путь НИЧЕГО не подавляет: ось-кандидат — фидбек индексирования («едешь по этой оси») и видна
  всегда, когда индексирование срабатывает; живая линия управляется своей настройкой. Пробовали
  гасить их под путём — откатили, они отвечают на разные вопросы.
- **AxisFlowCompass** (`src/AxisFlowCompass.*`) — Coin3D сцен-граф (блок B, сделан): контур с
  прозрачной заливкой + чёткая точка в центре; **ось Z не рисуется**; контур — квадрат (орто) /
  круг (радиальный) через `SoSwitch`; оси X/Y (цвет, толщина, начало, длина) из настроек;
  геометрия строится в локальной системе компаса и ставится `SoTransform`, поэтому `setPlane()`
  реально кладёт компас в рабочую плоскость. Видимость — корневой `SoSwitch`. Радиус задаётся в
  **мировых** единицах: перевод из пикселей делает `AxisFlowTool` по камере. **Живая направляющая**
  (guide, центр компаса → курсор) настраивается: вкл/выкл, стиль (сплошная/пунктир/точки/штрих-
  пунктир), цвет — из настроек (`LiveLine*`), применяется в `applySettings()`; API `applyGuideStyle()`.
- **AxisFlowPanel** (`src/AxisFlowPanel.*`) — плавающая Qt-панель (singleton при главном окне,
  `Qt::Tool | FramelessWindowHint`): заголовок + кнопка выключения, редактируемые поля с единицами,
  галки лока, и кнопка **системы координат** под полями. Кнопка НЕ дублирует режим: она
  переключает ридаут/ввод **Local ↔ World** (`_worldFrame`); режим орто/радиальный — на `Space`,
  виден по подписям полей (X/Y/Z ↔ D/A). World = те же оси компаса, но от мирового нуля
  (`value_i = localOffset_i + origin·axis_i`); ввод конвертируется обратно в локальный оверрайд.
  Поведение ввода (AccuDraw): первый символ заменяет живой readout (по полю, а не по устаревшему
  `_entryField` — иначе после Tab дописывалось); голая магнитуда получает **знак направления**
  курсора по оси (`signedByDirection`, см. `AxisFlowEntry.h`), явный знак важнее; при потере
  фокуса значение округляется до принятой точности и нормализуется по единицам (`reformatField`).
- **Время жизни вида и документа** (исправлено июль 2026). Закрытие файла уничтожает его вид, а
  вместе с ним viewer, граф сцены и камеру. Раньше это роняло FreeCAD тремя путями:
  (1) `CmdAxisFlowActivate::_tool` создавался как ребёнок вида, Qt удалял его вместе с видом, но
  сырой указатель в команде не обнулялся — следующее нажатие кнопки читало освобождённую память;
  (2) `~AxisFlowTool` звал `deactivate()`, а тот `_view->getViewer()` — дети удаляются в
  `~QObject`, когда деструктор `View3DInventor` уже отработал; (3) `g_session` в `AxisFlowPy.cpp`
  создавался БЕЗ родителя и переживал вид, после чего `ensureOwnSession()` видел `isActive() ==
  true` и продолжал работать с мёртвым видом. Ни одно место не подписывалось на закрытие
  документа. Сейчас: `_view` — `QPointer` (все 7 обращений под проверкой; тип вида в заголовке
  теперь подключается ПОЛНОСТЬЮ, а не форвард-объявлением — `QPointer<T>::data()` делает
  `static_cast<T*>` из `QObject*`, и без полного типа компилятор не знает об их родстве), инструмент слушает
  `destroyed` своего вида и в `onViewDestroyed()` сначала обнуляет `_view`, потом зовёт
  `deactivate()`, который целиком пропускает работу с графом сцены при нулевом виде;
  `g_session` создаётся через `makeSession()` — родителем вид плюс `destroyed`-хук, обнуляющий
  указатель с проверкой тождества (иначе отложенное удаление СТАРОГО инструмента обнулило бы
  НОВЫЙ); та же схема в `Command.cpp` (без контекстного объекта — `Gui::Command` не QObject);
  `ensureOwnSession()` дополнительно требует `g_session->view() == активный вид`, иначе после
  открытия другого файла компас оставался в старом окне, а точки шли в старый документ.
  **Одна живая сессия на всех** (`AxisFlowTool::current()`, статический `s_current`): владельцев
  инструмента ДВА — команда палитры и `g_session`. Раньше каждый смотрел только на свой указатель,
  поэтому «Activate» во время рисования создавал ВТОРОЙ инструмент на том же виде (два компаса,
  кнопка «не срабатывает» с первого раза). Теперь `activate()` сначала гасит чужую сессию, потом
  объявляет себя, `deactivate()` снимает захват, а кнопка палитры зовёт
  `performAction(CancelCommand)` перед деактивацией, чтобы потребитель `getPoint` успел завершить
  свою геометрию.
  Камера, за которой следит `SoNodeSensor`, теперь удерживается `ref()` на всё время наблюдения:
  без этого вид освобождал её под живым сенсором. На Python-стороне демо больше НЕ кеширует
  объект документа (закрытый файл превращал каждую транзакцию в обращение к мёртвой обёртке) —
  хранится только имя, документ ищется заново, а `_abandon_if_document_changed()` в `_on_point`
  и `_on_move` аккуратно завершает команду, если файл закрыли или переключились на другой.
- **AxisFlowTool** (`src/AxisFlowTool.*`) — на один 3D-вид. Владеет компасом. Standalone:
  Coin-колбэк (курсор + клики + клавиши) — это **основа будущего собственного ввода**.
  Adapter: курсор гонит Snapper. **Teardown отложен** (`deleteLater` инструмента и key-фильтра,
  `disconnect` от сервиса в `deactivate()`): завершать команду можно прямо из обработчика события,
  которым владеет сам инструмент, без use-after-free.
- **AxisFlowEventFilter** (`src/AxisFlowEventFilter.*`) — глобальный key-filter на `qApp`, нужен
  в ОБОИХ режимах: в собственном инструменте клавиши тоже не доходят до Coin-колбэка (Qt резолвит
  шорткаты раньше, см. §9.9). Решает только «где можно действовать» (`inScope`); «что значит
  клавиша» — `routeKey`. `claims()`/`isValueChar()` удалены как поглощённые роутером.
- **Двойные клавиши (связки).** Привязка — `KeyChord{first, second}` (`second == 0` = одиночная),
  карта `Hotkeys` теперь `map<KeyChord, AxisAction>`. Максимум ДВА нажатия — три требовали бы
  таймаута, а таймаут ставит поведение в зависимость от скорости печати. **Правило префикса:**
  клавиша либо одиночная привязка, либо первая в связке, но не то и другое — иначе нажатие
  префикса неразрешимо без ожидания. Проверяется в `Hotkeys::canBind/bind` (отказ, карта не
  меняется), в парсере `hotkeys.ini`, в загрузке из `ParameterGrp` и в диалоге. Состояние
  ожидания — `AxisFlowService::pendingPrefix()`; ожидание снимает ЛЮБОЕ следующее нажатие
  (`routeConsumesPrefix`, исключение — автоповтор удерживаемого префикса → `ChordHold`).
  Неизвестная вторая клавиша ГЛОТАЕТСЯ вместе с ожиданием: пропустить её дальше значило бы
  молча выполнить её обычное действие (опечатка `R`,`Y` заморозила бы поле Y). Пока ожидание
  активно, фильтр забирает все немодифицированные клавиши — иначе вторая клавиша утекла бы в
  одиночное действие или в шорткат камеры. Подтверждение точки сбрасывает ожидание.
  Дефолты: `RotateAboutX/Y/Z` = `R X` / `R Y` / `R Z` — поворот компаса на 90° вокруг СВОЕЙ оси
  (`AxisFlowSolver::rotateAboutAxis`, Родригес, Tier-1); в отличие от `RotateTop/Front/Side` они
  относительные. Панель показывает подсказку (префикс, затем по строке на вариант: «R →», «X about X», …) —
  ОТДЕЛЬНЫМ окном
  (`Qt::Tool | FramelessWindowHint | WindowDoesNotAcceptFocus` + `WA_ShowWithoutActivating`)
  рядом с панелью, слева если справа нет места. Строкой в layout она быть не может: меняла
  минимальный размер панели, и `adjustSize()` дрался с оконным менеджером («Unable to set
  geometry … minimum size» в Report view на каждое нажатие префикса). Окно не активируется и
  не поднимается — иначе каретка ушла бы из поля координат; следует за панелью (`moveEvent`) и
  гаснет вместе с ней (`hideEvent`).
- **Backspace/Delete забираются только при НАЧАТОМ вводе** (исправлено июль 2026). Раньше хвост
  `routeKey` отдавал их в `Backspace`/`ClearEntry` безусловно, а `isEditKey` вдобавок скармливал
  Delete в `QLineEdit` — поэтому при активном компасе Del никогда не доходил до FreeCAD и переставал

  падает в −1, когда поле снова опустело или точка подтверждена. Нет ввода — оба маршрута дают
  `Ignore`. Плюс механика Qt: одного `Ignore` мало, потому что `QLineEdit` ПРИНИМАЕТ

- **Команды преобразования** (июль 2026). `AxisFlow_Move` и `AxisFlow_Copy`, реализация —
  `axisflow_transform.py`, обычный потребитель `getPoint`, ядро геометрию по-прежнему не трогает.
  Схема взята у Draft (`draftguitools/gui_move.py`): выделение → две точки → коммит строкой
  команды. Отличие в пользу AxisFlow: после базовой точки компас стоит ТАМ, поэтому вторая точка
  вводится как смещение (X, 150, Enter), а не ищется мышью.
  Заимствованы три приёма Draft, намеренно: предпросмотр — призраки
  `draftguitools.gui_trackers.ghostTracker` (Coin-копии, документ не трогается до подтверждения);
  изменение уходит СТРОКОЙ через `Gui.doCommand` (`Draft.move(objs, vec, copy=…)`), поэтому
  попадает в стек отмены и эхом в консоль Python; и коммит ОТЛОЖЕН из колбэка — Draft делает это
  через свою очередь `todo`, мы через `QTimer.singleShot(0, …)`, потому что правка документа
  прямо из Coin-колбэка уже давала Access violation в команде линии.
  **Выделение**: есть — работаем с ним; нет — первый клик и выбирает объект под курсором, И
  служит базовой точкой (один клик вместо двух у Draft). Объект под курсором определяется
  `View.getObjectInfo()`, для чего понадобился новый `AxisFlow.getCursorPixel()`: выбор объекта —
  экранный запрос, а мировая точка на него не отвечает. Клик по пустому месту клик не расходует.
  **Расширение**: база `TransformTool` объявляет `needs` (сколько точек), `commands(objects,
  points)`, `modules` (что импортировать перед строками команд) и `pick_consumes_point`; плюс
  хуки `on_objects_ready()` (объекты известны — можно их осмотреть или отказаться) и `on_end()`
  (снять то, что поставил глобально). Move и Copy отличаются одним флагом. Rotate потребует трёх
  точек, Scale — двух плюс коэффициент, Array — плюс количество; сама машина не меняется.
  Офлайн-проверка — `tests/transform_harness.py` (заглушки FreeCAD/Gui/AxisFlow, без FreeCAD).
- **Режим выбора** (июль 2026, `_enter_pick_mode`/`_leave_pick_mode` в `TransformTool`). Пока
  команда ждёт объект, компас и панель спрятаны, курсор — стрелка с «хвостом»-мишенью. Как только
  объект известен, компас возвращается и дальше идёт обычный ввод.
  **Прятать через `AF.deactivate()` НЕЛЬЗЯ — грабли, на которые я наступил.** Выглядит логично:
  `onActiveChanged` документирует, что сессия остаётся жива, а активация только прячет UI. Но
  `AxisFlowTool::activate()` (строка 83) сам зовёт `AxisFlowService::instance().activate()`, поэтому
  следующий же `getPoint()` включал службу обратно, и пряталка не делала ровно ничего. Плюс
  `deactivate()` прячет заодно панель координат и меняет состояние службы.
  Правильный вызов — **`AF.setCompassVisible(bool)`**: флаг `_compassHidden` в сервисе, отдельный
  сигнал `compassHiddenChanged` (не `stateChanged` — тот летит на каждое движение мыши, и
  пересчитывать видимость по кадру значило бы писать в Coin-поле 60 раз в секунду). Панель при этом
  остаётся на месте, служба работает, ограничения применяются.
  **Видимость считается как `always || (isActive() && !compassHidden())`.** `AlwaysShowCompass`
  перебивает пряталку сознательно: настройка — явное указание, пряталка — удобство.
  **Флаг сбрасывается в `AxisFlowService::deactivate()`** и снимается из `_end()`, то есть на ВСЕХ
  путях выхода, включая Escape посреди выбора. Спрятанный компас не должен пережить команду.
  **Курсор ставится через QuarterWidget.** Python-API вида (`View3DInventorPy`) курсора не отдаёт:
  там `getObjectInfo`, `addEventCallback`, `getSceneGraph` и прочее, но ничего про курсор. Поэтому
  виджет ищется так же, как в Draft — обход детей `QMdiArea` с проверкой
  `inherits("SIM::Coin3D::Quarter::QuarterWidget")`. Сам курсор рисуется кодом (QPainter), без
  файла ресурса.
  **Подсветка остаётся посегментной.** Мы выбираем объект целиком (`addSelection(obj)` без
  подэлемента), но `SoFCUnifiedSelection` выбирает по ОТПУСКАНИЮ кнопки
  (`isButtonReleaseEvent`), а мы по нажатию (`AxisFlowTool.cpp:301`, `SoButtonEvent::DOWN`), и
  последнее слово за ним — он переписывает выделение на одно ребро. Лечится
  `View3DInventorViewer::setSelectionEnabled(false)` на время выбора (его `handleEvent` первой
  строкой проверяет это поле и пропускает событие дальше), но это C++.
- **Команда протяжки** (июль 2026). `AxisFlow_Extrude`, реализация — `axisflow_extrude.py`,
  подкласс `TransformTool`. Выбор проволоки → компас встаёт по её нормали → одна точка →
  `Part::Extrusion` с `Solid=False`. Смысл: ось X компаса СОВПАДАЕТ с направлением протяжки,
  поэтому высота набирается (X, 150, Enter), а не ищется мышью.
  **Базис строит `AF.alignCompassX`, а не `setPlane`.** `setPlane` нормирует три вектора по
  отдельности и НЕ ортогонализует их, а `localOf()` обращает матрицу транспонированием — верно
  только для ортонормированного базиса. Косой триплет дал бы тихо косую систему координат.
  `alignCompassX` лежал в солвере с самого начала мёртвым кодом; теперь выведен в сервис и Python,
  покрыт Tier-1 (5 кейсов) и Tier-2 (5 кейсов).
  **ТОЧНОСТЬ. Сырая точка снимается в ОДИНАРНОЙ точности** — `unprojectToCompassPlane` работает в
  мире Coin (`SbVec3f`, `SbLine`, `SbPlane`), причём начало и нормаль плоскости при входе
  урезаются из double. Float держит ~7 значащих цифр, поэтому на координатах порядка метра точка
  ложилась мимо плоскости на ~5e-5 мм, а солвер внеплоскостную компоненту пропускает как есть
  (`local.z` трогается только при локе Z). Каждая точка полилинии получала свой сдвиг, и линия,
  нарисованная плоской, плоской не была. Проверял численно: 4.8e-5 мм при допуске OCC 1e-7 —
  промах в 480 раз, отказ гарантирован.
  Лечится в источнике: `AxisFlowTool::snapToCompassPlane()` сажает точку на плоскость в double
  (`p - n*((p-o)·n)`), остаток ~1e-13 мм. Плющить всё подряд НЕЛЬЗЯ — привязка к геометрии вне
  рабочей плоскости обязана давать точку вне плоскости; на это есть тест
  `AnOutOfPlaneRawPointIsNotSilentlyFlattened`.
  **Допуск плоскостности масштабируется по габариту** — миллионная доля диагонали габаритного
  ящика (`_planar_tol`), около микрона на метровой проволоке. Нужен и для чертежей, сделанных до
  починки, и для честно привязанных точек. **Тот же допуск идёт в `is_straight_line`**, и это не
  косметика: прямая с шумом не является строго прямой, строгая проверка отправила бы её в
  `find_plane`, а тот с ослабленным допуском вернул бы плоскость с ПРОИЗВОЛЬНОЙ нормалью — ровно
  та ловушка «privileged directions», о которой предупреждает докстринг Draft.
  **У прямого отрезка плоскости НЕТ**, и это свойство FreeCAD, а не наше: `is_straight_line()` в
  `draftgeoutils` существует именно потому, что `Part.Shape.findPlane()` назначает прямым
  проволокам произвольную плоскость («creating privileged directions»), а `find_plane()` для них
  возвращает None. Фолбэк — горизонталь: одиночный отрезок тянется вверх и даёт вертикальную
  стену. Вертикальный отрезок так не может (поверхность схлопнулась бы), для него направление —
  мировой X. **`DraftGeomUtils.get_normal()` НЕ использовать**: он в конце разворачивает нормаль к
  камере (`if normal.getAngle(v_dir) < 0.78: normal = normal.negative()`), и сторона протяжки
  зависела бы от угла обзора. Берётся `find_plane(shape).Axis` без флипа.
  **Фильтр выбора** — `Gui.Selection.addSelectionGate` с объектом, имеющим `allow(doc, obj, sub)`.
  FreeCAD проверяет гейт внутри `addSelection`, поэтому он закрывает и 3D-вид, и дерево, и наш
  собственный клик под курсором, и отвечает запрещающим курсором со строкой в статус-баре.
  Выделение, сделанное ДО запуска команды, гейт не отменяет — поэтому `on_objects_ready()`
  проверяет ещё раз; правило при этом живёт в одном месте (`wire_normal()`).
  **Клик выбора не расходует точку** (`pick_consumes_point = False`): компас нельзя навести, не
  зная проволоки, поэтому двойное назначение первого клика (как у Move) здесь невозможно.
  **Превью — свой Coin-узел, не `ghostTracker`.** Тот даёт только `SoTransform` поверх статической
  копии (move/rotate/scale), а протяжка меняет саму геометрию; пересборка призрака на каждое
  движение — это OCC-экструзия плюс новый граф сцены на кадр. Проволока раскладывается
  `discretize` ОДИН раз (в ней могут быть дуги), на движение переписываются только координаты
  `SoCoordinate3`, `numVertices` задаётся один раз. Граф сцены удерживается `ref()` — тот же урок,
  что в демо-линии.
  **Escape отменяет протяжку, но раскладку это НЕ меняет.** Escape глобально привязан к
  `FinishLine` (`AxisFlowHotkeys.cpp:44`), потому что для демо-линии это «закончить полилинию и
  продолжить рисовать» — ценнее единообразия. Смысл завершения определяет потребитель: `Extrude`
  переопределяет `_on_finish()` в `_end()`, у Move/Copy остаётся «начать заново». Обратная кавычка
  (`CancelCommand`) работает везде и всегда.
  **Якорь — ближайшая точка проволоки к месту клика**, а не нулевая вершина: на длинной стене
  компас оказывался в метрах от того места, куда смотрел пользователь. Точка попадания приезжает
  из `getObjectInfo` (ключи x/y/z) через `TransformTool.pick_point` и проецируется на проволоку
  через `distToShape`, а не берётся сырой: попадание приходит из Coin в одинарной точности, да и
  проволока выбирается с допуском, поэтому сырая точка лежит РЯДОМ с проволокой, а не на ней;
  проекция заодно прижимает результат к концам. Выделение, сделанное до команды, никто не кликал —
  там по-прежнему первая вершина.
  **Косая протяжка разрешена намеренно**: `Dir` у `Part::Extrusion` — произвольный вектор, а
  перпендикулярность обеспечивают локи (X / SmartLock). Направление нормируется, высота уходит в
  `LengthFwd` — так она остаётся одним редактируемым числом в свойствах. Исходная проволока
  прячется, иначе рисуется дважды внутри собственного результата.
  Офлайн-проверка — `tests/extrude_harness.py` (18 проверок, заглушки включая `draftgeoutils`).

  Открывается командой `AxisFlow_Settings`. Ограничение: пока открыт, не подхватывает внешние
  изменения (`changed()` не проброшен в Python), перечитывает при повторном открытии.
- **axisflow_snap.py** — опциональный Draft-адаптер с СОБСТВЕННЫМ публичным API
  (`install()`/`uninstall()`/`is_installed()`/`set_debug()`/`set_hold_typing()`), вызывается
  ПОЛЬЗОВАТЕЛЕМ вручную, автоматически нигде не грузится и на палитру не вынесен. Это НЕ то же
  самое, что рабочий мост `axisflow_snapping.py` (его C++ зовёт на каждом движении мыши): здесь
  компас показывается поверх ЧУЖОЙ работающей команды Draft/BIM как кооперативный визуализатор,
  зеркалящий лок Draft, но сам не ограничивающий и клавиш не забирающий. Документирован в README;
  удалять нельзя без потери этой возможности. Оборачивает `Snapper.snap`, зеркалит
  `Snapper.mask` в UI (display-only), продлевает штатную защёлку Draft (`setMouseMode` +
  `mouse_delay_input_start`), выключает наше ограничение (`setConstrainEnabled(False)`).

## 6. Настройки (блок C, `ParameterGrp`)

Ветка: `User parameter:BaseApp/Preferences/Mod/AxisFlow`.

**Полная таблица опций живёт в README.md (раздел Settings) и больше НЕ дублируется здесь.**
Копия в этом файле разъехалась с кодом по тринадцати дефолтам из двадцати одного (компас
перенастраивали, а таблицу не трогали: `CompassSize` 120 против 100, `AxisStartPct` 0.15 против
0.80, `LiveLineEnabled` true против false, индексирование выключено против включённого…) и
потеряла пять живых ключей. Две таблицы, которые надо править синхронно, синхронными не бывают,
поэтому осталась одна.

Расхождение теперь ловится автоматически: `TestAxisFlow.test_readme_settings_table_matches_the_defaults`
разбирает таблицу README и сверяет имена и дефолты с `AxisFlow.getDefaultSettings()`. Новая опция
или изменённый дефолт без правки README роняют Tier-2. Источник истины в коде —
`struct AxisFlowDefaults` в `AxisFlowSettings.h`.

Всего 26 опций плюс ключи клавиш `Hotkey.<Action>` (ASCII, список Qt-кодов; `""` = не назначено).

Формат значения `Hotkey.<Action>`: запятая разделяет АЛЬТЕРНАТИВЫ, пробел соединяет две клавиши
одной связки (`"16777220,16777221"` — Return и numpad Enter; `"82 88"` — связка R X). В
`hotkeys.ini` то же именами: `SmartLock = Return, Enter` и `RotateAboutX = R X`.

Действия для ключей клавиш (дефолты = hotkeys.ini): `ToggleMode` (Space), `ConfirmPoint` (P),
`SmartLock` (Return/Enter), `LockX/Y/Z/D` (X/Y/Z/D), `SetOrigin` (O), `RotateTop` (T),
`RotateFront` (F), `RotateSide` (S), `RotateByView` (V), `RotateCycle` (E), `FinishLine`
(Escape), `ToggleSegmentMode` (M), `CancelCommand` (backtick), **связки** `RotateAboutX` (R X), `RotateAboutY` (R Y),
`RotateAboutZ` (R Z); без дефолта: `ToggleActive`, `ClearLocks`, `CancelEntry`. Клавиша `R` —
префикс, поэтому собственной привязки не имеет и иметь не может (правило префикса). Семантика Lock*: заморозить поле на
текущем значении (галка ставится, поле перестаёт следовать за мышью), повторно — снять; LockX/Y
только в орто, LockD только в радиальном, LockZ везде (при привязке пинит высоту в системе
компаса). Enter СТАВИТ точку (commit набранных координат). **Escape = FinishLine**
(завершить текущую линию, сессия живёт), **backtick = CancelCommand** (завершить всю команду).
`SmartLock`/`ClearLocks`/`CancelEntry` — без дефолтной клавиши, доступны через API. `setSetting`-имена
опций: те же, что в таблице, camelCase (`compassSize`, `liveLineEnabled`, `liveLineStyle`, `liveLineColor`, …).

GUI-редактор — `axisflow_settings.py` (команда `AxisFlow_Settings`): двухстолбцовый грид, тип
поля по значению, применение на лету (см. §5). Все 26 опций там представлены; каждая
завязана на `AF.setSetting`, что шлёт `changed()` → компас/панель обновляются мгновенно.

## 7. Статус

**Готово и в проекте:**
- Солвер (орто/полярный, **локи-фиксации полей** — единый механизм с оверрайдами + `LockBit`-маска,
  включая полярные D/A; smart-lock двумя полями; keyboard-оверрайды, world↔local, nearestAxis),
  сервис-синглтон с сигналами, настройки на `ParameterGrp`, карта хоткеев.
- Компас Coin3D (контур+заливка+точка, квадрат/круг, без Z, поворот к WP, «всегда показывать»,
  постоянный размер в пикселях) + настраиваемая **живая линия** (вкл/выкл, стиль, цвет).
- Панель: редактируемые числовые поля (в полярном режиме теперь ТРИ поля — D/A/Z), активное
  поле по nearestAxis, Tab-цикл, галки лока (галка = поле заморожено: лок ИЛИ набранное значение;
  клик по галке замораживает/освобождает; в адаптере display-only зеркало Draft-маски —
  «движение вдоль X» показывается галками на Y и Z),
  «просто печатай», кнопка **Local/World**; ввод AccuDraw — знак по направлению
  (`AxisFlowEntry.h`), первая цифра заменяет, округление/нормализация единиц при потере фокуса.
- Инструмент/стейт-машина `Idle/Tracking/Finished`, continue-режим; **Escape = FinishLine**
  (завершить линию, сессия живёт), **backtick = CancelCommand**; **teardown отложен**
  (`deleteLater`+`disconnect`), завершать команду безопасно из своего же обработчика.
- Публичный `getPoint(callback, movecallback, last, continuous, finishcallback)`; мост
  `GetPointBridge`. Рабочая плоскость подхватывается потребителем (`AF.setPlane` из активной WP).
- **Анимация компаса** (июль 2026). Два вида, оба «только отображение» — солвер меняет плоскость и
  начало координат мгновенно, компас догоняет. Поворот — slerp. Перемещение — перекрёстное
  затухание: призрак, замороженный на старом якоре, гаснет, а живой компас одновременно проявляется
  на новом. Время у обоих из `CompassRotateAnimation`.
  **`setOrigin` зовётся на КАЖДОЕ движение мыши** (`AxisFlowTool.cpp:683`), почти всегда с тем же
  значением. Без отсечки по 1e-6 в начале `setOrigin` анимация перезапускалась бы каждый кадр и
  компас навсегда застревал бы в полупрозрачном мерцании. Это главная ловушка этого места.
  **Один таймер, две дорожки.** У поворота и перемещения свои `_animT0`/`_moveT0` и флаги
  `_rotActive`/`_moveActive`; сенсор снимается только когда обе закончились. Дорожки пересекаются
  штатно — подтверждение точки при `CompassFollowDirection` и переносит якорь, и доворачивает.
  **Призрак — глубокая копия** (`SoNode::copy(TRUE)`) узла `_bodySep`, снимаемая в момент старта.
  Синхронизировать её не надо: она живёт полсекунды и показывает то, чем компас был. Живая линия,
  путь и маркеры индексирования в `_bodySep` НЕ входят — призрак, тянущий живую линию от старого
  якоря к текущему курсору, выглядел бы как баг. Известная косметика: `SoCallback` хранит функцию
  в обычном указателе, а не в поле, поэтому `copy()` её не переносит, и центральная точка призрака
  рисуется квадратной, а не круглой.
  **Грабли этой замены (стоили чёрного контура вокруг компаса).** `SoBaseColor` задаёт ТОЛЬКО
  диффузный цвет, поэтому обводка контура наследовала прозрачность заливки от материала выше.
  У `SoMaterial` есть собственное поле `transparency` со значением 0 по умолчанию — обводка стала
  непрозрачной и превратилась в жёсткое тёмное кольцо. Сейчас обводка берёт цвет заливки и её же
  прозрачность (пишется в `applySettings`), `kOutlineColor` оставлен в исходнике на случай
  возврата старого вида. Урок общий: замена `SoBaseColor` на `SoMaterial` — это не только
  «добавилось поле», это ещё и сброс унаследованной прозрачности.
  **Цветовые узлы тела — `SoMaterial`, а не `SoBaseColor`**: у второго нет поля прозрачности, и
  затухать он не умеет. При модели освещения `BASE_COLOR` рисуется diffuseColor, поэтому вид не
  изменился. Наложение прозрачности на поддерево (`setOverride`) НЕ подходит: в Coin биты
  наложения для diffuseColor и transparency намеренно совпадают (ради совместимости с SGI/TGS
  Inventor), поэтому принудительная прозрачность заодно схлопнула бы красную и зелёную оси в один
  цвет. Проверено по `src/nodes/SoMaterial.cpp`.
  **Выключается целиком** галкой `CompassAnimation`. Она сложена в длительность
  (`_animDurationS = enabled ? setting : 0`), поэтому выключение уводит код ровно в те ветки, что
  уже были для нулевой длительности: мгновенный `applyRotationNow`, мгновенный прыжок, ни
  призрака, ни глубокой копии, ни заведённого сенсора. Смысл именно в этом — затухание стоит
  кадров при рисовании линии, и полувыключенная анимация всё равно бы за них платила.
  **`rebuildGuide()` в тике зовётся только при активном ПОВОРОТЕ.** Перемещение направляющую не
  меняет: якорь встаёт на место до первого тика, а затухание переписывает только прозрачности.
  Раньше звалось безусловно и било по худшему сценарию — полилиния переякоривает компас после
  каждой точки, то есть на каждый сегмент приходился шторм перестроений.
  **Затухание — модуляция, а не запись**: у каждого материала запоминается его собственная
  прозрачность, и пишется `base + (1-base)*e`, а по завершении она восстанавливается ТОЧНО.
  Иначе первое же перемещение сделало бы полупрозрачную заливку контура непрозрачной.
  По той же причине `applySettings()` и `setVisible(false)` сначала доводят анимацию до конца.
- **Палитра**: шесть команд с иконками (`Activate`, `DrawLine`, `Move`, `Copy`, `Extrude`, `Settings`) +
  значок верстака; **живой диалог настроек** (`axisflow_settings.py`).
- **Демо-линия** (вне ядра): многосегментная, собственное Coin-превью, транзакции/undo на каждую
  линию, снятие выделения с готовой линии; Escape — новая линия, backtick — конец.
- Draft-адаптер (`axisflow_snap.py`); зеркало Draft-маски переведено на display-only канал
  `setDisplayLock` (реальные локи в адаптере не создаются).
- **Переработка локов (июль 2026):** галка = заморозка поля. LockX/Y/Z/D фиксируют поле на текущем
  значении; SmartLock фиксирует два «чужих» поля в 0 (движение строго вдоль ближайшей оси; в
  полярном — угол на 0/90/180/270 + Z=0); после постановки точки локи сбрасываются (per-point).
  Старый одноосевой `setAxisLock` (зануление off-axis) удалён; Python `lockAxis` принимает
  'x'|'y'|'z'|'d'|'a'|'none' и стал идемпотентной установкой, `getState()['lock']` заменён на
  `getState()['locks']` (dict по слотам). Ось-кандидат остаётся видимой, пока лок прижимает
  точку к оси (SmartLock-пара, поле, замороженное ровно в 0, полярный угол кратный 90°):
  `IndexingInput.lockedOnAxisX/Y` взводят `axisActive` ДО гейтов кадра/масштаба — это фидбек
  лока, не мягкое индексирование; геометрию компас берёт из solved-точки, она уже на оси.
- **Индексирование живой линии** (локальный фрейм): снап по дистанции (точка-кандидат на конце
  живой линии при приближении длины к запомненной «индексированной дистанции») и по осям (ось-
  кандидат вместо живой линии при приближении к оси X/Y). Допуск в пикселях, чистая математика в
  `AxisFlowIndexing.h`, снап зашит в `getSolvedPoint()`, визуалы в компасе, 6 новых настроек,
  Python-API (`setIndexedDistance/clearIndexedDistance`, поля в `getState`), Tier-1+Tier-2 тесты.
  **Разрешение индексирования осей — ПО ОСЯМ, а не глухим запретом** (исправлено июль 2026).
  Индексирование стоит ПОСЛЕ локов и переписывает координаты (`getSolvedPoint()` берёт `r.lx/ly/lz`),
  поэтому обнулять можно только СВОБОДНУЮ компоненту: ось X схлопывает `ly` и требует свободного
  слота Y, ось Y схлопывает `lx` и требует свободного X. Раньше стоял общий гейт `axisLocked =
  inPlaneLocked()` — любой лок выключал индексирование целиком, и после блокировки X по горячей
  клавише снап по оси пропадал. Теперь `IndexingInput` несёт `fixedU/fixedV/fixedN`
  («слот занят», ТИПОВАННЫМ значением тоже — его индексирование тоже не имело права затирать) и
  `blockAxisIndexing` только для радиального режима, где проекция на ось меняет и дистанцию, и
  угол сразу. В ветке привязки `lz` обнуляется лишь при свободном Z. `inPlaneLocked()` остался без
  потребителей.
  Нюансы: точка-кандидата гасится во время ввода координаты в поле (введённое значение важнее
  снапа); пока активен любой кандидат — точка (снап длины) или ось (обнуление перпендикулярной
  компоненты) — поля X/Y/Z (или D/A) синхронизируются со снапнутой точкой, иначе показывают сырой
  курсор. Точки (центр компаса и кандидат) круглые (`GL_POINT_SMOOTH`, линк с `OpenGL::GL`).

- **Объектные привязки (Draft Snapper)**: своих не пишем — зовём FreeCAD'овские через тонкий
  Python-мост `axisflow_snapping.py` (`snap(x,y,ox,oy,oz,has_origin) -> (px,py,pz,hit)`),
  который дёргает `AxisFlowTool::querySnap` по C-API (модуль кэшируется, ошибки глушатся —
  привязки никогда не ломают инструмент). `constrain=False`: ограничения наши, Draft не должен
  применять их второй раз. `lastpoint` = центр компаса — без него не работают extension/
  parallel/perpendicular/ortho. Факт привязки определяется по видимости снап-маркера Draft
  (`Snapper.tracker.Visible`), т.к. `snap()` возвращает точку всегда.
  **`noTracker=True` не гасит линию Draft при СРАБОТАВШЕЙ привязке.** Флаг проверяется только на
  ветке «ничего не привязалось» (`if self.trackLine and lastpoint and (not noTracker)`); когда
  привязка выигрывает, работает `Snapper.snapToObject()`, а там `if self.trackLine and lastpoint:`
  без всякого флага — `noTracker` в эту функцию даже не передаётся. Итог: тонкая сплошная линия
  дефолтного цвета Draft (в светлой теме чёрная) от `lastpoint` (= центр компаса) к привязанной
  точке, поверх нашей живой линии и пути. Гасим явно: `_hide_track_line()` в `axisflow_snapping.py`
  сразу после `snap()` и в `hide()`; на `Snapper.tracker` (маркер, по которому определяем факт
  привязки) это не влияет. Проверено по исходнику `draftguitools/gui_snapper.py`.
  Приоритеты: введённое значение → лок поля → привязка → индексирование → сырой курсор.
  Привязанная точка становится «точкой размещения» (`getLocalOffset` берёт её вместо курсора),
  поэтому лок проецирует именно её, а поля X/Y/Z показывают реальные 3D-координаты привязки
  (компонента Z больше не обнуляется). Сырой курсор при этом сохраняется — по нему «удержание
  оси» решает, по какой оси едет пользователь.
  **Удержание оси при привязке** (безусловное, бывшая настройка «SmartLock» в разделе Snapping —
  удалена в июле 2026): если в момент привязки курсор шёл вдоль оси в допуске индексирования,
  точка ОСТАЁТСЯ на этой оси — привязка отдаёт вдоль-осевую координату, прочие компоненты
  обнуляются, ось-кандидат горит. Курсор вне оси — привязка авторитарна, кандидаты гаснут.
  Гейты: включено осевое индексирование; при явном локе ветка не нужна — лок прижимает сам.
  Идея: точка всегда остаётся на оси, вдоль которой двигается курсор. Ключ `SmartLock` в
  `ParameterGrp` больше не читается (остатки на диске безвредны). Палитра привязок —
  переиспользуем команды `Draft_Snap_*` в своём тулбаре (состояние общее с Draft/BIM).

  по всем фичам этой волны — 101 строка на язык, 23 новых (Behaviour-опции, Control/View hotkeys,
  SetOrigin/Rotate*-метки, Freeze-формулировки), во всех

- **Анимация поворота компаса** («Compass rotation animation (s)», ключ `CompassRotateAnimation`,
  float 0..2 c клампом, дефолт 0.5; 0 = мгновенно): чисто визуальная — солвер переключает
  плоскость сразу, компас доворачивается slerp'ом со smoothstep-изингом на `SoTimerSensor`
  (~60 fps) внутри `AxisFlowCompass::setPlane`. Ключевое: display-базис `_u/_v/_n` (по нему
  считается живая линия) интерполируется в ногу с трансформом (`applyRotationNow` выводит его из
  той же SbRotation), иначе конец линии «отклеивался» бы от курсора на время анимации; финальный
  кадр ставит точный целевой базис (без числового дрейфа). Первый setPlane после создания —
  мгновенный (активация не должна «выплывать» из identity); ретаргет на лету стартует из текущей
  интерполированной позы, так что быстрые T-F-S цепляются плавно. Сенсор гасится в деструкторе.
- **Пакет view/origin-действий и починка ToggleActive (июль 2026):**
  `SetOrigin` (O) — перенос origin компаса в текущую solved-точку (со снапом) БЕЗ подтверждения
  точки: `setOriginToCursor()` в сервисе не эмитит `pointConfirmed`, команда рисования указание
  игнорирует; чистит typed-значения/локи, взводит follow-референс; компас перепривязывается сразу
  (синк origin добавлен в `onServiceStateChanged` тула). `RotateTop/Front/Side` — фикс-базисы
  через `setPlane` (Front: n=−Y, v=+Z, u=+X; Side: n=+X, v=+Z, u=+Y); `RotateCycle` (E) — цикл
  Top→Front→Side с досевом индекса из явных Rotate*; `RotateByView` (V) — сервис эмитит
  `alignToViewRequested`, тул строит базис из ориентации камеры (right/up/back). **ToggleActive
  починен**: фильтр событий при выключенном сервисе теперь перехватывает ровно одну клавишу —
  привязанную к ToggleActive (ShortcutOverride+KeyPress, с inScope-гейтом) — раньше выключение
  было односторонним. Дефолты built-in переписаны зеркально hotkeys.ini (Insert свободен,
  ConfirmPoint=P, SmartLock=Enter). Диалог: вкладка Hotkeys разделена на «Control hotkeys» и
  «View hotkeys»; ConfirmPoint/ClearLocks/CancelEntry из окна убраны (остались биндуемыми через
  API/ini, метки для конфликт-диалога — в `_HIDDEN_ACTION_LABELS`). Адаптер unbind'ит все новые
  буквы (P/O/T/F/S/V/E) — однобуквенные шорткаты Draft внутри его команд не крадутся.
- **«Компас следует направлению»** («Compass follows direction», ключ `CompassFollowDirection`,
  int 0..2 с клампом, по умолчанию 0=Выкл, enum-строка в Behaviour): при подтверждении точки
  компас довворачивается по отрезку «предыдущая точка → новая». Режим 1 («оставить Z») —
  проекция отрезка на текущую плоскость становится осью u, нормаль не меняется; режим 2
  («полностью») — u = направление отрезка, нормаль берётся максимально близкой к старой
  (Грам-Шмидт; отрезок вдоль старой нормали → новой нормалью становится старая v). Математика —
  `AxisFlowSolver::rotateToDirection(dir, keepNormal)` (Tier-1). Поворот происходит в `confirm()`
  ДО переноса origin и гейтится флагом `_hasFollowRef`: свежая сессия (`beginInput` →
  `clearFollowReference()`) не вертит компас по отрезку от «прошлогоднего» origin; засеянная
  база (`setOrigin`, т.е. `last` в getPoint) флаг взводит — первый же отрезок валиден. Внешний
  `setPlane`/`resetPlane` поворот перекрывают штатно.
- **«Переход фокуса при движении»** («Focus advance on movement», ключ `FocusAdvanceOnMove`,
  по умолчанию включён, раздел Behaviour): после набора значения в поле X (Y) осознанное движение
  курсора (> 6 px, порог в `focusAdvanceExceeded` из `AxisFlowEntry.h` — чистый предикат под
  Tier-1) завершает ввод и переносит каретку в смежное поле Y (X); в полярном — D↔A. Введённое
  значение остаётся оверрайдом, поле переформатируется как при blur. Якорь перевзводится каждым
  принятым нажатием (`pushFieldValue` — единая воронка ввода), так что дрожание мыши во время
  набора ввод не крадёт; без камеры (`viewScale()<=0`) не срабатывает. Дизарм: Enter/Tab/blur/
  Escape/пустое поле/подтверждение точки. Поле Z в переходе не участвует. После перехода
  взводится `_advanceHold`: авто-таргетинг по nearestAxis заморожен (иначе курсор, всё ещё
  прижатый к прежней оси, украл бы каретку обратно); холд снимают Tab, Escape и постановка точки.
- **Знак-от-направления стал опциональным** («Smart negative direction», ключ
  `SmartNegativeDirection`, по умолчанию включён): без знака введённая величина берёт знак
  направления курсора по оси (гейт — в `pushFieldValue` панели; чистое правило
  `signedByDirection` в `AxisFlowEntry.h` не изменилось). Выключено — знак буквально как введён.
  Раздел настроек «Snapping» переименован в «Behaviour», галка живёт там.
- **Вкладка Hotkeys в диалоге настроек**: третий раздел (после Compass / Live Line) со списком
  действий, кнопкой захвата клавиши (клик → «Press a key…» → нажатие), кнопкой ✕ и «Restore
  default keys». Отказ от Ctrl/Alt/Meta (их фильтр всё равно не перехватывает), предупреждение
  при конфликте (карта — key→action, поэтому назначение отбирает клавишу у другого действия).
  Новое C++/Python API: `setHotkeys(action, [codes])` (список — чтобы не терять вторую клавишу
  у `ConfirmPoint`) и `resetHotkeys()` (чистит только `Hotkey.*`, прочие опции не трогает).
- **`package.xml` требует `<subdirectory>./</subdirectory>`** в `<content><workbench>`: если тега
  нет, FreeCAD подставляет `<name>` и ищет `Mod/AxisFlow/AxisFlow/InitGui.py` → верстак молча

- **Дефолтные хоткеи в `hotkeys.ini`** (россыпью в Mod, не в `.qrc`): правятся без пересборки.

- **i18n (по политике FreeCAD)**: интерфейс следует глобальному языку FreeCAD (Preferences →

## 9. Ошибки сборки, УЖЕ решённые (не наступать снова)

1. `LNK1104 python311.lib` → `target_link_directories(... "${PYTHON_ROOT}/libs")`.
2. «No module named» → нужен `.pyd`: `set_target_properties(... PREFIX "" SUFFIX ".pyd")`.
3. «DLL load failed» → `os.add_dll_directory(...)` в `InitGui.py`.
4. python311 vs python312 → пиннинг на pixi-env (`Python3_ROOT_DIR`, `Python3_FIND_STRATEGY
   LOCATION`, `Python3_FIND_REGISTRY NEVER`, `Python3_FIND_VIRTUALENV FIRST`) + чистая реконфигурация.
5. `C2196`: в Coin `SoKeyboardEvent::RETURN` и `ENTER` — один код (65293), нельзя оба как `case`.
6. Не-ASCII в runtime-строках: `QLatin1String("\u2014")` на MSVC даёт мусор (UTF-8 байты как
   Latin-1). Использовать `QString(QChar(0x2014))`. Символы без глифа (⏻ U+23FB) — заменять на
   `QStyle::standardIcon`.
7. **Путь установки — всегда спрашивать у FreeCAD, не хардкодить.** CMake берёт путь через
   `getUserAppDataDir()` и добавляет `Mod/AxisFlow`. В этой среде он разрешается в
   `%APPDATA%\FreeCAD\Mod\AxisFlow` (ранее предполагали версионированный `v1-1\Mod` — здесь не
   подтвердилось). Если поставить не туда, куда смотрит запущенная FreeCAD, воркбенч не
   регистрируется, `InitGui.py` не выполняется, `import AxisFlow` → `ModuleNotFoundError`,
   `Gui.activateWorkbench` → `KeyError`. Переопределяется `-DFREECAD_MOD_DIR=...`.
8. Имя воркбенча для `Gui.activateWorkbench(...)` — **`AxisFlowWorkbenchPy`** (имя класса в
   `InitGui.py`), а не `AxisFlow`/`AxisFlowWorkbench`.
9a. **Модель фокуса (главное про ввод).** Каретка ВСЕГДА стоит в активном поле панели
   (`AxisFlowPanel::focusActiveField()`). Пока `QLineEdit` в фокусе, он сам поглощает цифры,
   Backspace и стрелки — и глобальные шорткаты FreeCAD не срабатывают. Ронять фокус нельзя
   нигде: `clearFocus()` после Escape приводил к тому, что следующая цифра уходила в
   `Std_ViewTop`. Клик в 3D-виде отдаёт фокус вьюпорту, поэтому `confirmPoint()` возвращает
   каретку обратно. Первый набранный символ очищает поле (иначе допишется к живому readout).
   Панель — окно `Qt::Tool`, значит для каретки её надо `activateWindow()`.
9. **Клавиши нельзя ловить в Coin-колбэке.** FreeCAD вешает на голые цифры глобальные `QAction`
   (`2` → `Std_ViewTop` и т.п.), а Qt разрешает шорткаты **до** доставки события виджету 3D-вида.
   Итог: «просто начни печатать» молча меняет вид камеры. Правильный механизм — фильтр на `qApp`,
   который принимает `QEvent::ShortcutOverride` для «своих» клавиш (тогда `QAction` не срабатывает
   и приходит обычный `KeyPress`) и там же делает работу. То же касается `Space`
   (`Std_ToggleVisibility`).
10. **GoogleTest на MSVC+pixi: компилировать из исходников, не линковать библиотеку.** Отдельная
    `gtest.lib` в этой связке (clang-флаги pixi на MSVC-линии) не подхватывалась — `MakeAndRegister­
    TestInfo` оставался unresolved. Решение: добавить `gtest-all.cc`+`gtest_main.cc` прямо в цель
    тест-раннера и поставить include gtest первым. Заголовки и определения гарантированно совпадают.
11. **`InitGui.py`: раздельные globals/locals.** FreeCAD исполняет init-скрипт так, что имена,
    присвоенные на верхнем уровне (`_icons_dir`), НЕ видны внутри тела класса. Обращение к ним из
    тела `class Workbench` даёт `NameError`. Ставить такие значения (например `Icon`) на верхнем
    уровне после `class`, а тело держать литеральным.
12. **Кнопка на палитре ≠ окно.** Команда живёт в C++ (`Command.cpp`); чтобы кнопка появилась,
    нужна свежая `.pyd` с зарегистрированной командой И **полный перезапуск** FreeCAD (Python-
    верстак строит тулбар из `self.list` раз за сессию). Открытие окна из консоли работает и без
    зарегистрированной команды, поэтому «окно есть, кнопки нет» = не пересобрано/не перезапущено.
    Отсутствие иконки кнопку НЕ прячет (нерезолвнутый `sPixmap` → кнопка без картинки). Проверка:
    `"AxisFlow_Settings" in FreeCADGui.listCommands()`.
13. **Иконки грузятся с диска** через `FreeCADGui.addIconPath(Resources/icons)` в `InitGui.py`;
    `Resources/AxisFlow.qrc` пустой (плейсхолдер). Имя `sPixmap` должно совпадать с именем SVG без
    расширения. Новую иконку достаточно положить в `Resources/icons/` (в install попадёт через
    `install(DIRECTORY Resources ...)`), рекомпиляция не нужна.
14. **`wireTracker` из Draft не для списка точек.** Его конструктор и `update()` ждут Part-wire
    (`.Vertexes`), не list Vector — падал молча. В демо превью рисуется собственным Coin-узлом.

## 10. Известные ограничения

- Одна активная сессия ввода (следствие синглтона, §3.3).
- **Единицы в полях не вводятся.** Валидатор полей панели (`[0-9.,+\-]*`) пропускает только
  цифры, знак и разделитель, поэтому «1,5 m» / «2 ft» набрать нельзя, хотя `parseQuantity`
  (`Base::Quantity`) их понимает и значение уже хранится в базовых единицах. Лечится возвратом
  букв в валидатор с повторным гейтом клавиш-действий по пустому полю (тогда буква на непустом
  поле = суффикс единицы). До этого момента формулировки «unit-aware» в README и `package.xml`
  — аванс.
- Компас: цвет заливки и обводки не настраиваемые (настраивается только прозрачность заливки).
- Собственный ввод есть; впереди — полноценные относительные/абсолютные режимы ввода сверх
  текущей World-конверсии по осям.
- Teardown сессии безопасен на Qt-путях (backtick/Escape). Остаётся узкий Coin-side случай:
  `AF.endSession()`, вызванный синхронно внутри point-callback не-continuous потребителя, всё ещё
  делает `unref` Coin-узла на его собственном стеке. Демо (continuous + отмена через Qt) не задевает.
- Sketcher не поддержан (свой C++ `DrawSketchHandler`, отдельная большая задача).
- Диалог настроек (`axisflow_settings.py`) применяет изменения на лету, но пока открыт не
  подхватывает внешние изменения (например, кнопку «Toggle live line»): `changed()` не проброшен
  в Python. Перечитывает значения при повторном открытии. Лечится поллингом или пробросом сигнала.
- Панель только плавающая (`Qt::Tool`); докируемый вариант обсуждён, но не сделан.
- Draft-адаптер: значение, впечатанное вручную в поле Draft, подчиняется локу Draft, но не нашему;
  это нормально — в адаптере лок и есть Draft'овый.

   (отменить набор → снять лок, `AxisFlowPanel::cancelInput()`) остаётся в коде, но без дефолтной
   клавиши (можно повесить через `setHotkey`); при желании вернём «эскалацию» Escape.
   Превью линии между точками — ✅ сделано (собственный Coin-узел в демо, не Draft-трекер).
5. **Относительные/абсолютные координаты**, перенос компаса в последнюю подтверждённую точку.
6. **Блок A — переключатель «глобальные ↔ система компаса».** ✅ Сделано. Кнопка под полями
   (`_frameBtn`, Local/World) переключает ридаут И ввод: World = те же оси компаса от мирового
   нуля (`value_i = localOffset_i + origin·axis_i`), ввод конвертируется обратно в локальный
   оверрайд. Режим орто/радиальный остаётся на Space (кнопку больше не дублирует).
7. **Публичный `getPoint`-API с колбэками.** ✅ Сделано.
   `AxisFlow.getPoint(callback=None, movecallback=None, last=None, continuous=False, finishcallback=None)`.
   `callback(point, ok)` — точка (`Base.Vector`, ok=True) или отмена (None, ok=False);
   `movecallback(point)` — живая точка на каждом движении; `finishcallback()` — Escape/FinishLine
   (завершить линию, сессия живёт); `continuous=False` (дефолт) — одна точка, `True` —
   последовательность до отмены. Мост слушает и `AxisFlowService::finishRequested`. Мост `GetPointBridge` (QObject) держит колбэки
   с `Py_INCREF`, зовёт под `Base::PyGILStateLocker`, слушает `AxisFlowTool::pointConfirmed` и
   `AxisFlowService::cancelRequested`/`cursorMoved`. `getPoint` поднимает СВОЙ инструмент
   (`activate(true)`, клавиатура/каретка). Одна активная операция за раз; повторный вызов из
   колбэка (паттерн «вторая точка линии») безопасен — старый мост не трогает состояние нового.
8. **Демо-команда «линия»** — ✅ Сделано и расширено. `axisflow_demo.py` (вне ядра):
   `axisflow_demo.line()` гоняет полный цикл через `getPoint(continuous=True, finishcallback=…)`,
   строит `Draft.make_wire` с транзакцией/undo (каждая линия — свой шаг Undo), синхронизирует
   **Дуговые сегменты** (июль 2026): клавиша `M` (`ToggleSegmentMode`) переключает следующий
   сегмент между прямой и дугой. Ядро о дугах не знает — действие только РЕТРАНСЛИРУЕТСЯ:
   `AxisFlowService::segmentModeRequested` → `GetPointBridge` → новый `modecallback` у
   `getPoint`, ровно по образцу `finishcallback`. Дуга задаётся ТРЕМЯ точками: начальная уже
   есть (конец предыдущего сегмента), кликами ставятся конечная точка и точка на дуге. Касательность
   НЕ навязывается, поэтому стыки сегментов под любым углом; три точки сами задают плоскость,
   поэтому ограничений по 3D нет. Хранение: `_pts` — вершины, `_bulges[i]` — точка на дуге для
   сегмента, заканчивающегося в `_pts[i]`. Вырожденная дуга (три точки на одной прямой) молча
   становится отрезком, нулевой сегмент отбрасывается. Коммит: если дуг нет — прежний
   `Draft.make_wire` (остаётся редактируемым по точкам), если есть — `Part::Feature` с
   `Part.Wire` из смешанных рёбер, непараметрический (Draft Wire дуг не держит). Временный
   объект привязки несёт ту же смешанную геометрию, поэтому привязки к центрам и серединам
   СВОИХ дуг работают. **Компас во время дуги**: после подтверждения конечной точки `placePoint`
   ставит начало координат на неё, но точка на дуге отмеряется от ХОРДЫ, поэтому демо переносит
   компас на её середину (`AF.setBasePoint` — новый Python-API, двигает якорь БЕЗ подтверждения
   точки, то есть без `pointConfirmed` и без повторного входа в колбэк потребителя). После
   замыкания дуги компас уходит на её конец (иначе остался бы на точке выпуклости, откуда ломаная
   не продолжается); при отмене дуги переключением режима возвращается на последнюю вершину.
   Превью запоминает ГРАФ СЦЕНЫ, к которому прицепилось (`self._sg`, с
   `ref()`): спрашивать граф активного вида при снятии неверно, как только пользователь переключил
   документ — сепаратор лежит в графе старого вида, а `removeChild()` на чужом графе это удаление
   по индексу −1. Офлайн-проверка бухгалтерии дуг и сценария смены документа — `tests/demo_arc_harness.py`
   (заглушки FreeCAD/Part, запускается без FreeCAD).
   активную рабочую плоскость (`AF.setPlane`), рисует собственное Coin-превью, снимает выделение
   с готовой линии. Escape — новая линия, backtick — конец команды. Внутренностей AxisFlow не знает.
   **Привязка «сам к себе»** (июль 2026): подтверждённая часть текущей линии живёт во временном
   объекте документа `Part::Feature` с именем `AxisFlow_Drawing`, который переписывается после
   каждой точки. Причина: `Snapper` рассматривает ТОЛЬКО объекты документа — цели он выбирает
   через `View.getObjectsInfo()` и резолвит через `ActiveDocument.getObject()`, поэтому узел Coin
   в графе сцены для привязки не существует, каким бы видимым он ни был. Тот же приём применяет
   сам Draft: его инструмент линии создаёт `Part::Feature` при старте команды и переписывает
   `Shape` по ходу. Итог: конечные точки, середины, перпендикуляры и пересечения по собственной
   недорисованной линии работают штатным снаппером, без своей математики. Объект стилизован под
   старое превью (оранжевый, 2 px) и обязательно `Selectable = True` — иначе снаппер его
   пропустит; Coin-превью ужалось до «резиновой нити» от последней точки к курсору, чтобы
   подтверждённая часть не рисовалась дважды. Удаляется ПЕРЕД любым коммитом (`_on_finish`,
   `_end`), поэтому в сохранённый документ и undo не попадает; при сбое (`Part` недоступен) всё
   откатывается на прежнее полностью-Coin превью, рисование не ломается.

## 12. Конвенции

- `QT_NO_KEYWORDS` → `Q_SIGNALS/Q_SLOTS/Q_EMIT`.
- Типы: `Base::Vector3d`, `Base::Matrix4D`; Coin — `SbVec3f`.
- Комментарии в коде — английский; общение — русский.
- `PreCompiled.h` — первым инклюдом.
- Q_OBJECT-классы → в `qt6_wrap_cpp(MOC_SOURCES ...)` (AUTOMOC не используется). Классы без
  сигналов/слотов (Hotkeys, EventFilter) в MOC-список не добавлять.
- Никаких не-ASCII символов в runtime-строках (см. §9.6).
- Иконки — SVG в `Resources/icons/`, имя = `sPixmap`; грузятся через `addIconPath` (диск), не qrc.
- Путь Mod — только через FreeCAD (`getUserAppDataDir()`), не хардкодить.
- Чистую тестируемую логику выносить в header-only без Qt/Coin (примеры — `AxisFlowEntry.h`,
  `AxisFlowIndexing.h`, `AxisFlowKeyRouting.h`) и крыть Tier-1 gtest. После правок — прогонять
  `run_tests.bat` до продолжения.
- **Клавиши разбираются в одном месте.** Новое действие = строка в `hotkeys.ini` + строка в
  `Hotkeys::setDefaults()`; никаких switch по кодам клавиш в call-site. Связка задаётся так же
  (`RotateAboutX = R X`), но её первая клавиша обязана быть свободна от одиночной привязки. Политика — `routeKey`,
  Qt-переходник — `keyContextFromEvent`; call-site только исполняют вердикт. Клавиатуру в
  Coin-колбэке не ловить (§9.9).
- Ответы держать сжатыми, прозой, если не просят иначе.

## 14. Релиз и распространение

AxisFlow — **компилируемый C++-верстак** (`AxisFlow.pyd`). Addon Manager его не соберёт: внешние
верстаки в нём обязаны быть Python-only. Официальные пути — хостить прекомпилированные бинарники
самому либо вливаться в ядро FreeCAD. Выбран первый: **GitHub Releases с готовым ZIP** под
конкретную версию/платформу FreeCAD.

**ABI-замок:** `.pyd` грузится только в FreeCAD с совпадающими Python/Qt/Coin ABI — собирать против
той же дистрибуции, что у пользователей, и проверять ZIP на чистой установке. Имя вида
`AxisFlow-0.2.1-win64-FC1.1.zip`.

Инструменты: `make_release.bat` (собирает рантайм-папку `dist/AxisFlow` — только `.pyd`+`.py`+
`Resources`+`package.xml`+`LICENSE` — и жмёт ZIP через PowerShell), `package.xml` (метаданные),
`LICENSE` (полный LGPL-2.1), `RELEASE.md` (чеклист выпуска и инструкция установки), раздел
Installation в README. Опции на будущее: коммит прекомпилированной `.pyd` в репозиторий для
Addon-Manager custom-repo (одна платформа/ABI), Windows-инсталлятор (Inno/NSIS).
